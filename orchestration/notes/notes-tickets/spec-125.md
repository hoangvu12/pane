# #125 Windows power features: hotkeys that never fail, paste and selected text, Switch Windows, system commands and Run
['ready-for-agent', 'specification']

## Problem Statement

Pane on Windows does the basics but stops where Windows users expect a launcher to take over the desktop.

- **Hotkeys fail where Raycast's work.** Pane registers every global hotkey with `RegisterHotKey`, so it can only use a letter, a digit, F1 to F12 or Space with Ctrl, Alt or the Windows key. A shortcut another application registered, or one Windows keeps (Alt+Space, Win+R, Win+.), is refused with an error. The Windows key pressed alone, a double tap of a modifier (Ctrl Ctrl), and a side-specific modifier (Right Ctrl, Right Alt) cannot be used at all. Raycast for Windows makes all of these work, and a fresh Raycast install opens on the Windows key.
- **Pane cannot act on the application the user came from.** It does not know which application was in front before it, cannot paste into it, and cannot read the text selected there. Clipboard history can only copy an item back, the user then switching and pasting by hand. ADR 0037 gives every command a host function to paste into the application that was in front before Pane; nothing on Windows does that yet.
- **No way to switch windows.** Pane cannot list the open windows or bring one to the front.
- **No system commands.** Locking the computer, sleeping, turning the displays off, changing the volume, muting the microphone, emptying the Recycle Bin or switching dark mode all need another tool.
- **No Run.** Win+R's Run dialog is the Windows user's command line for programs, Control Panel applets, consoles, `shell:` and `ms-settings:` addresses and folders, and Pane has nothing like it.

## Solution

Pane becomes a first-class Windows tool, keeping the small core (ADR 0001): the system work is done by host capabilities, any extension can use them (the more flexible choice for authors), and the features users see are default extensions they can disable one by one.

- **Hotkeys that never fail for a reason Windows gives.** Pane still registers a binding with `RegisterHotKey` when Windows accepts it. When Windows refuses it, or it is a kind `RegisterHotKey` cannot express (the Windows key alone, a double tap of a modifier, a side-specific modifier), Pane recognizes it through a low-level keyboard hook of its own instead, so a refused shortcut is never an error. The hook is installed only while a binding needs it and is guarded the way Raycast guards its own: a watchdog that reinstalls it when Windows silently removes it, its code kept in memory, a high-priority thread, recovery from modifiers stuck down, and tagged input Pane injects itself. An optional game mode pauses Pane's hotkeys while a game is in front. ADR 0039 records this amendment of ADR 0016.
- **The Windows key opens Pane on a fresh install** (the user's decision, ADR 0039), like Raycast's "Replace Start Menu": once the hook can recognise the Windows key tapped alone, a fresh install's Open Pane hotkey is the Windows key alone; the Start menu stays reachable from the taskbar and Ctrl+Esc. Until the hook lands, the default stays Ctrl+Alt+Space. macOS and Linux keep their defaults.
- **Paste and selected text.** Pane follows which application was in front before it and implements ADR 0037's paste on Windows: it hides, brings that application back, pastes with a tagged Ctrl+V, and restores the user's clipboard. A new host function reads the text selected in that application, through UI Automation in a worker process of Pane's own and, failing that, a simulated copy.
- **Switch Windows**, a default extension listing the open windows as Alt+Tab does, with their applications' names and icons, bringing the chosen one to the front.
- **System Commands**, a default extension of no-view commands (ADR 0037) using documented Windows APIs: lock, sleep, hibernate, displays off, screen saver, log out, restart, shut down, volume, microphone mute, Recycle Bin, dark mode, HDR, and a few more. Each toggle answers with a HUD of the state it ended in, and the destructive ones ask first. Restart and Shut Down force applications to close, like Raycast's (ADR 0040).
- **Run**, a default extension that runs what Win+R runs, sharing Win+R's own history in both directions, with completions while typing and an elevated run through the Windows prompt (ADR 0033).
- Switch Windows, System Commands and Run join Pane's default extensions, enabled by default and each disableable in Manage extensions (the user's decision, ADR 0040, extending #60's set; Windows Settings joins with the "Applications done properly" specification (#124)).
- **Later, flagged:** a UI Access helper so hotkeys, paste and selected text also work while an elevated application is in front.

On macOS and Linux the hotkey kinds, paste, selected text, Switch Windows, System Commands and Run are explained as unavailable through Pane's existing platform-availability mechanism, and the extension contract answers their calls with an explanation; their own slices are proposed follow-ups.

## User Stories

### Hotkeys

1. As a Windows user on a fresh install, I want Pane to open with the Windows key tapped alone, as Raycast does, so that Pane replaces the Start menu as the place I start everything.
2. As a Windows user who takes the Windows key for Pane, I want Win+<key> combinations (Win+E, Win+D, Win+L…) to keep working, so that only the lone tap changes.
3. As a Windows user who takes the Windows key for Pane, I want the Start menu not to open as well when I tap it, so that the two do not fight.
4. As a Windows user who takes the Windows key for Pane, I want the Start menu still reachable from the taskbar and Ctrl+Esc, so that I can always get back to it.
5. As a Windows user who set another Open Pane hotkey, or whose installation predates this change, I want a "Use the Windows key" choice beside the Open Pane hotkey in Settings (Raycast's "Replace Start Menu"), so that I can make that switch in one step.
6. As a Windows user, I want to bind a double tap of a modifier (Ctrl Ctrl, Shift Shift, Alt Alt) to Pane or to a command, so that I can summon things without a chord.
7. As a Windows user, I want to bind a single tap of a side-specific modifier (Right Ctrl, Right Alt), so that I can use a key I otherwise never press.
8. As a Windows user, I want side-specific modifiers in chords (Right Alt+Space), so that the left keys keep their usual meaning.
9. As a Windows user, I want Pane to warn me, and refuse, when a single tap and a double tap of the same modifier would both be bound, so that one never swallows the other.
10. As a Windows user, I want a shortcut that another application or Windows already registered (such as Alt+Space or Win+R) to work for Pane rather than be refused, so that I can choose any combination I like.
11. As a Windows user, I want to be told, when I take a shortcut Windows or another application uses, what that shortcut does there and that Pane now takes it first while Pane runs, so that I am not surprised when the old meaning stops.
12. As a Windows user, I want shortcuts no program can take (Win+L, Ctrl+Alt+Delete) refused with that reason, so that Pane never pretends to have them.
13. As a Windows user, I want to bind Win+R to Run and Win+. to an emoji command, so that Pane can replace Windows' own pickers.
14. As a Windows user, I want to see on each hotkey's row whether it works through Windows' registration or through Pane's keyboard hook, so that I can understand a binding that behaves differently.
15. As a Windows user, I want the hotkey recorder to capture the Windows key alone, a double tap and the side of a modifier while I press them, without the Start menu opening, so that recording these kinds is as easy as a chord.
16. As a Windows user, I want more keys allowed in hotkeys (F13 to F24, punctuation, arrows, Home, End, Page Up and Page Down, Insert, Delete, Enter, Tab and numpad keys distinct from their counterparts), so that I can use the keys my keyboard has.
17. As a Windows user, I want my hotkeys to keep working after my computer was locked, after a UAC prompt or after sleep, so that a missed key release never leaves Ctrl or the Windows key stuck down for Pane.
18. As a Windows user, I want Pane's hotkeys to keep working after Windows silently removes a slow keyboard hook, so that a busy moment does not break them until I restart Pane.
19. As a Windows user, I want Pane's keyboard hook never to slow down my typing in other applications, so that installing Pane costs me nothing while I type.
20. As a Windows user who runs PowerToys Keyboard Manager or AutoHotkey, I want keys Pane injects not to be remapped by them, and keys they inject not to be mistaken for mine, so that the tools coexist.
21. As a Windows user, I want Pane to install no keyboard hook while none of my bindings needs one, so that a plain setup stays as light as it is today.
22. As a gamer, I want an optional game mode that pauses all of Pane's hotkeys while a game is in front, so that my game gets every key.
23. As a gamer, I want game mode to recognise a full-screen game by itself and to let me name programs to treat as games, so that windowed games are covered too.
24. As a gamer, I want Pane's hotkeys to come back by themselves when the game leaves the front, so that I never have to switch them on again.
25. As a Windows user, I want the Open Pane hotkey and every command hotkey to get these kinds alike, so that there is one hotkey model.
26. As a Windows user, I want a no-view command's hotkey (such as Lock Screen) to run it without showing Pane's window (ADR 0037), so that a hotkey for a system command acts at once.
27. As a macOS or Linux user, I want a hotkey of a kind my system does not support here (a lone modifier, a double tap, a side) explained on its row as unavailable on my system, so that a record copied from a Windows machine is not mysterious.
28. As a user, I want a hotkey that cannot work while an elevated application is in front explained, so that I know why it did nothing there.

### The previous application, paste and selected text

29. As a Windows user, I want Pane to know which application was in front before I opened it, ignoring the taskbar, the Start menu, Alt+Tab and Pane's own windows, so that paste and selected text reach the right application.
30. As an extension author, I want to read the name and icon of that application (the front application), so that my paste action can say "Paste to Notepad".
31. As a clipboard-history user, I want to paste an item straight into the application I came from, so that I do not switch and press Ctrl+V myself.
32. As a user, I want my clipboard to hold what it held before once a paste is done, so that pasting through Pane does not lose what I had copied.
33. As a user, I want the text Pane puts on the clipboard to paste kept out of Pane's clipboard history and Windows' own (Win+V), so that one paste does not leave copies behind.
34. As a user, I want Pane to wait until the target application is really in front before it pastes, so that the text never goes into the wrong window.
35. As a user, I want a paste into a window that does not respond, or into an application running as administrator, to fail with a clear message and leave the text on the clipboard, so that I can paste it myself.
36. As an extension author, I want a host function that reads the text selected in the application in front before Pane, so that I can write translate, search or transform-selection commands.
37. As a user, I want reading the selection to be quick and never to freeze Pane, even when the application in front is slow, so that a selection command opens at once.
38. As a user, I want reading the selection to work in browsers and editors built on Chromium as well as in native Windows controls, so that it works where I select text most.
39. As a user, I want my clipboard unchanged after a command read my selection through a simulated copy, and that copy kept out of Pane's clipboard history, so that reading is invisible.
40. As a user, I want a command that finds no selection told so, not given an empty string silently, so that it can explain.

### Switch Windows

41. As a Windows user, I want a Switch Windows command listing the windows Alt+Tab would show, with their titles, applications and icons, so that I can find a window by typing.
42. As a Windows user, I want hidden helper windows, tool windows, owned dialogs and suspended Store app windows left out, so that the list holds only what I can switch to.
43. As a Windows user, I want windows on other virtual desktops listed only if my Alt+Tab is set to show all desktops, and marked as elsewhere, so that the list agrees with Windows.
44. As a Windows user, I want the window I was in before Pane listed first and the rest by how recently they were in front, so that switching back is one keystroke.
45. As a Windows user, I want Enter to bring the chosen window to the front, restoring it if minimized, so that switching is one action.
46. As a Windows user, I want progressive web app windows shown with their own app's name and icon rather than the browser's, so that they look as they do on the taskbar.
47. As a Windows user, I want to search windows by title and by application name, so that "slack" finds every Slack window.
48. As a Windows user, I want actions on a window (close, minimize, maximize, restore, keep on top) from the action panel, so that I can manage windows without touching them (later slice, with the "Extension commands like Raycast" specification (#120)'s action panel).
49. As a Windows user, I want an action that cannot reach an elevated window to say so, so that a silent failure is never mistaken for success.

### System commands

50. As a Windows user, I want Lock Screen, Sleep, Hibernate, Turn Off Displays, Start Screen Saver, Log Out, Restart and Shut Down as commands, so that power and session control are a few keystrokes away.
51. As a Windows user on a Modern Standby laptop, I want Sleep to put the computer into its standby the way Windows does, so that the command does not fail or do something unexpected.
52. As a Windows user without hibernation, I want Hibernate to say that hibernation is not available on this computer, so that I know why nothing happened.
53. As a Windows user, I want Restart, Shut Down and Log Out to ask first, with a "don't ask again" choice, so that a mistyped query never ends my session.
54. As a Windows user, I want Restart and Shut Down to force applications closed, as Raycast's do, after the confirmation, so that an application with unsaved work cannot hold up a restart I confirmed; and Log Out not to be forced, as in Raycast.
55. As a Windows user, I want Volume Up, Volume Down, Mute and Set Volume (with a number), each answering with the volume it ended at, so that I can control sound from the keyboard.
56. As a Windows user in calls, I want Toggle Microphone Mute to mute every microphone if any is on, or unmute them all, and to say which it did, so that one command is a reliable mute.
57. As a Windows user, I want Open Recycle Bin and Empty Recycle Bin (asking first), so that I can manage deleted files from Pane.
58. As a Windows user, I want Toggle System Appearance to switch Windows between light and dark and say which it chose, so that one command flips my theme.
59. As a Windows user with an HDR display, I want Toggle HDR, saying the state it ended in, or that no HDR-capable display was found, so that I can switch HDR for a game or a film.
60. As a Windows user, I want Show Desktop, Toggle Hidden Files and Eject Removable Drives, so that common Explorer chores are commands too.
61. As a Windows user, I want each system command to be a root result I can give an alias or a hotkey, so that I can lock or mute without opening Pane.
62. As a Windows user, I want a toggle's HUD to show for 1.2 seconds, or 3 seconds when it failed (ADR 0035), so that feedback is brief.
63. As an extension author, I want the same system operations through a host import, so that my own extension can lock, mute or change the volume.

### Run

64. As a Windows user, I want a Run command that runs anything Win+R runs: programs by name or path with arguments, Control Panel applets, management consoles, folders, network paths, `shell:` and `ms-settings:` addresses and other registered schemes, and environment variables in paths, so that I can drop the Run dialog.
65. As a Windows user, I want Run's history to be Win+R's own, so that what I ran in either appears in both.
66. As a Windows user, I want to delete an entry from Run's history and have it gone from Win+R too, so that one history stays clean.
67. As a Windows user, I want Run to find a program installed after Pane started, so that I do not restart Pane after installing a tool.
68. As a Windows user, I want completions while I type (programs on the path and in App Paths, applets, consoles, registered schemes and environment variables), so that I type less.
69. As a Windows user, I want to run a program as administrator from Run, through Windows' own prompt (ADR 0033), so that elevated tasks need no other tool.
70. As a Windows user, I want a run I cancelled at the elevation prompt, or one that failed, to stay out of the history and say why, so that history holds only what ran.
71. As a Windows user, I want a path with spaces and arguments (`C:\Program Files\Tool\tool.exe -a`) to run without quotes, as Win+R does, so that I type what I would type there.
72. As a Windows user, I want "Run in terminal" to run a command line in Windows Terminal when it is installed, or in the shell itself otherwise, so that console tools stay open to read.
73. As a Windows user, I want Run offered as a fallback for any text, and usable through an alias, so that typing a command line in root search can run it.

### Elevated applications (later, flagged)

74. As a Windows user who runs some programs as administrator, I want Pane's hook-based hotkeys, paste and selected text to work while such a program is in front, so that elevated windows are not a dead zone (later slice).

### Cross-cutting

75. As a user, I want each of Switch Windows, System Commands and Run to be a default extension, enabled from the start and disableable on its own, so that I have them on my first day and keep only what I use.76. As an extension author, I want the new host imports in Rust, JavaScript and TypeScript alike, so that my language is not a limit.

## Implementation Decisions

### Decision provenance

- **Decided by the user:** this specification's scope (the hook fallback with its safeguards, a refused shortcut never being an error, an optional game mode, paste into the previous application and selected-text capture, Switch Windows, documented system commands, Run sharing Win+R's history, and a UI Access helper as a later, flagged slice); the Windows key alone as the fresh-install Open Pane hotkey on Windows once the hook exists, like Raycast's "Replace Start Menu", with Ctrl+Alt+Space kept until then and macOS and Linux defaults unchanged (ADR 0039, "Hotkeys fall back to a keyboard hook, a refused shortcut is no longer an error, and the Windows key opens Pane on a fresh install", amending ADR 0016); Switch Windows, System Commands and Run as default extensions enabled by default, each disableable in Manage extensions (ADR 0040, "Default extensions grow to include Switch Windows, System Commands, Run and Windows Settings", extending #60's set); Restart and Shut Down forcing applications closed like Raycast, with the destructive confirmation kept, and Log Out not forced, as in Raycast (ADR 0040); ADR 0033 (extensions may run system programs, optionally elevated through the Windows prompt); ADR 0037 (a command declares its mode; host functions, including paste into the application in front before Pane, decide what happens after it runs; a no-view command's hotkey runs it without showing the window); ADR 0035's HUD and toast durations; the direction to take Raycast's features and choose the more flexible option for extension authors, never copying Raycast's code or assets.
- **Proposed defaults in this specification**, not separately confirmed: the binding record's new syntax and kinds; the timing values (tap and double-tap windows, timeouts, debounces); which shortcuts stay refused; the "Show the taskbar when Pane opens" setting and registering Ctrl+Alt+Space instead when the hook cannot be installed (both proposed by ADR 0039); game mode's detection signals and off-by-default state; clipboard restore behaviour; the selected-text worker and its failure pause; listing the new default extensions only in the Windows default set (proposed by ADR 0040); the system command catalog beyond the brief's list; and the slicing.
- **Proposed defaults the user delegated ("like Raycast, as flexible as possible"):** paste on macOS and Linux X11 is unavailable for now, with copying as the fallback (stated the same way in the "Extension commands like Raycast" specification (#120)); elevated program runs are Windows only.
- **Coordination call (made by the coordinator):** the front application and selected-text host functions are declared by the "Extension commands like Raycast" specification (#120), as additions to ADR 0037's host functions; this specification implements them, and paste, on Windows.

### Hotkeys: registration first, the hook as fallback

- **Dispatch per binding.** For each binding Pane wants active, the Windows adapter tries `RegisterHotKey` (without repeat) when the binding is a plain chord it can express. It uses the keyboard hook when: Windows refuses the registration (another application has it, or Windows keeps it); the binding is a lone tap of a modifier (the Windows key, Right Ctrl); a double tap of a modifier; uses a side-specific modifier; needs a key `RegisterHotKey` cannot tell apart (a numpad key from its counterpart); or game mode has paused registrations. A refused registration is never an error to the user; the row says it works through Pane's keyboard hook and, for a shortcut Windows or a known application uses, what that shortcut did there.
- **Still refused,** with the reason: shortcuts no program can intercept (Win+L, Ctrl+Alt+Delete); a binding another of Pane's bindings already has (the command's name is given, as today); a single tap and a double tap of the same modifier together ("cannot coexist"). Pane's own guards stay (a chord needs Ctrl, Alt or the Windows key unless it is a lone or double modifier tap; Ctrl with only a letter or digit is refused because applications use it), proposed. The Windows reserved list becomes warnings (Alt+F4, Alt+Space, Win+D, Win+E, Win+R and others say what Windows does with them) rather than refusals, except the two above.
- **Kinds and record (proposed shape).** A binding is a chord (modifiers, each any side or a named side, plus a key), a single tap of one modifier, or a double tap of one modifier. The key set grows to F1 to F24, punctuation by its US-layout name, arrows, Home, End, Page Up, Page Down, Insert, Delete, Enter, Tab, Space and numpad keys distinct from their counterparts. Records gain a textual form for these (for example a side prefix such as `rctrl`, and `tap:` and `double:` kinds), and the hotkey record and the host settings' Open Pane field move to a new version that still reads version 1. Display names follow Windows: "Win", "Right Ctrl", "Ctrl Ctrl".
- **The Windows key alone.** While the Windows key alone is bound, the hook recognises a tap (press and release with no other key between, within a short window, proposed 500 ms) and, so that Explorer does not open the Start menu, injects a tagged neutral key before the release reaches Explorer. Any other key pressed with it passes through untouched, so Win+<key> keeps Windows' meaning.
- **The fresh-install default (the user's decision, ADR 0039).** On Windows, once this hook exists and recognises the Windows key alone (slice 2 below), a fresh install's Open Pane hotkey is the Windows key alone, as Raycast's is; until then it stays Ctrl+Alt+Space. An existing installation keeps the Open Pane hotkey it has. If the hook cannot be installed, Pane registers Ctrl+Alt+Space instead and shows why (proposed by ADR 0039). macOS (Option+Space) and Linux (Ctrl+Alt+Space) are unchanged. As in Raycast's "Replace Start Menu", a "Use the Windows key" choice beside the Open Pane recorder, shown while another hotkey is set, sets it in one step and says the Start menu stays on the taskbar's Start button and Ctrl+Esc. A General-page setting, "Show the taskbar when Pane opens" (proposed by ADR 0039, as Raycast offers), shows an auto-hiding taskbar while the launcher is open so the Start button stays one click away. The hotkeys document and the first-run text change with this slice (the "Quick fixes" specification (#129) corrects the document for what ships before it).
- **Double taps** are two presses of the same modifier with nothing between, within a window (proposed 400 ms); the first press passes through to applications.
- **Recording.** On Windows the recorder (the Open Pane recorder, the Shortcuts page and the hotkey screen) asks the hook adapter for a recording session while it listens: the hook reports the raw key state and holds the keys back from Windows, so the Windows key alone, double taps and sides can be pressed without the Start menu opening. Escape and Tab still cancel. The session ends when the recorder stops listening, the window loses focus or Pane quits. On macOS and Linux the recorder is unchanged and offers none of the new kinds.
- **The hook's safeguards.**
  - *Only while needed:* the hook is installed when the first binding needs it and removed when none does.
  - *A dedicated thread* at the highest thread priority (not a raised process priority, so the rest of Pane is unaffected), whose callback only updates a small state machine and posts a message: it never allocates on the hot path, takes no lock the window or runtime holds, and calls nothing in GPUI or the extension runtime.
  - *Kept in memory:* the hook's code and data pages are locked after raising the process's minimum working set by what they need, so a trimmed working set cannot page-fault the callback past Windows' hook timeout. If Windows refuses, the diagnostics say the pages are not pinned.
  - *Liveness watchdog:* a message-only window receives raw keyboard input in the background; when several raw key events arrive without the hook seeing them, Windows has removed the hook, and Pane installs it again, counting attempts and giving up with a diagnostic after repeated failures within a short time.
  - *Stuck modifiers:* the state machine re-reads the modifiers' real state from the system when a key event contradicts it, on session unlock and on resume, so a release missed while the secure desktop, the lock screen or a UAC prompt had the keyboard never leaves a modifier down for Pane.
  - *Tagged injected input:* every key Pane injects (the Start-menu mask, paste, the simulated copy) carries Pane's own tag in its extra information; the hook passes tagged events through untouched, and keys other tools inject are passed through without counting as the user's. Whether Pane also tags its keys with the documented marker of PowerToys Keyboard Manager or AutoHotkey while they run, so they leave them alone, is an open detail.
- **Diagnostics:** Settings' Keyboard page shows, per binding, how it is dispatched, and the hook's health (installed, reinstalled n times, pages pinned); Copy Diagnostics (the "Making extensions easier to build" specification (#128)) includes them.
- **Elevated applications:** while an application running as administrator is in front, Windows does not deliver its keys to a hook of a normal process, so hook-based bindings do nothing there; registered ones still work. Rows of hook-based bindings say so once the hook is used, and the later UI Access slice lifts it.
- **No-view commands** run from their hotkey without showing the window (ADR 0037, amending ADR 0016); a view command's hotkey opens it in the window as today.
- **Game mode** (Windows only, off by default): while on, Pane checks on each foreground change (a system foreground event, not a timer) whether the window in front is a game: Windows reports a full-screen Direct3D application in front through its documented notification state, or the program is one the user listed in game mode's settings. While a game is in front, every Pane hotkey (the Open Pane hotkey too) is released and the hook passes everything through; they return when the game leaves the front. The tray icon's tooltip says hotkeys are paused. Reading Windows' game configuration store, as Raycast also does, is a possible later signal (it is undocumented).
- **Other systems:** macOS (Carbon hot keys) and X11 (key grabs) keep today's registration. The new kinds are explained there through the unavailable-row mechanism ("Not available on macOS: double-tap hotkeys work only on Windows for now"), and the extended key set is offered where those adapters can register the key. Modifier taps on macOS (an event tap, needing the Input Monitoring permission) and on X11 are proposed follow-ups.
- ADR 0039 amends ADR 0016 with the hook fallback, that a refused shortcut is no longer an error, and the Windows key as the fresh-install default.

### The previous application, paste and selected text

- **Front application tracking (Windows).** A system foreground event hook, out of process and cheap, records the last window in front that is not one of Pane's own windows and not a shell surface (the taskbars and their overflow, the desktop, Alt+Tab and task view, Start, Search, the lock screen, input and notification hosts, Widgets). It starts when Pane starts. A host function every command has answers the **front application**: its name and icon (through the "Applications done properly" specification (#124)'s window-to-application identity) and whether a target exists. This is an addition to ADR 0037's list of host functions; the "Extension commands like Raycast" specification (#120) declares it (coordinator's call), and this specification implements it.
- **Paste (ADR 0037's host function, implemented on Windows):** Pane hides its window (as the close-window host function does), puts the text on the clipboard tagged as not to be kept (`ExcludeClipboardContentFromMonitorProcessing`, `CanIncludeInClipboardHistory` 0 and `CanUploadToCloudClipboard` 0, so neither Pane's clipboard history nor Windows' keeps it), brings the target to the front (on a worker with a timeout: skip a window that is not responding, try the plain foreground call, then attach to the foreground thread's input and try again; a newer request supersedes an older one), waits until the target really is in front (proposed up to 500 ms), sends a tagged Ctrl+V, then restores the clipboard's earlier contents after a short delay (proposed 500 ms) unless the clipboard changed meanwhile. Restore copies back every format held in ordinary memory (text, rich text, HTML, images as device-independent bitmaps, file lists); formats rendered on demand or held as graphics handles cannot be restored and are documented as lost. The restore is tagged too. Text only in this slice; images and files are a follow-up.
- **Paste failures** are honest: no target, a target gone or not responding, a target that did not come to the front, or a target running as administrator (detected from its process's elevation before injecting, since Windows would silently drop the keys) each answer the command with a failure saying why. The text stays on the clipboard, still tagged so history stays clean, and the earlier contents are not restored, so the user can paste it by hand.
- **Selected text (a new host function every command has, declared by the "Extension commands like Raycast" specification (#120)):** first UI Automation, in a worker process of Pane's own (Pane's program started with an internal argument, owned like a helper and ended when Pane quits), asked with a timeout (proposed 2.5 s) and replaced when it times out; three failures within ten minutes pause UI Automation reads for ten minutes. The worker reads the focused element's text selection, waking a Chromium-based application's accessibility tree on first contact and retrying shortly after. If UI Automation gives nothing, a simulated copy: Pane saves the clipboard, sends a tagged Ctrl+C to the target, waits for the clipboard's sequence number to change (proposed up to 500 ms), reads the text and restores the clipboard. Pane's clipboard history ignores clipboard changes during that window; Windows' own history may keep the target's copy, since Pane cannot mark another application's copy (documented). No selection answers "nothing is selected", distinct from a failure.
- **Clipboard history's primary action** can then become "paste into the previous application" with copy as the second action, once the "Extension commands like Raycast" specification (#120)'s action panel lands; that change belongs to the Clipboard History extension and is listed as a follow-up.
- **Other systems:** on macOS and Linux (X11 included) the front application, paste and selected text answer "not available on this system yet", and the SDK's paste helpers fall back to copying and saying so (proposed default, delegated; the "Extension commands like Raycast" specification (#120) states it the same way). Proposed follow-ups: Linux X11 (synthetic Ctrl+V through the X test extension, the PRIMARY selection for selected text, no permission) and macOS (the Accessibility permission, synthetic Command+V, the accessibility selection). Wayland stays unavailable.

### Switch Windows

- **Host capability** `pane:extension/windows`, any command may use it (pattern of ADR 0015), Windows only; elsewhere every call answers "not available on this system" and the default extension declares `windows` alone.
- **Which windows count** (documented calls only): visible, unowned top-level windows that are not "no activate", not tool windows unless forced onto the taskbar, not removed from the taskbar by their application, not a Store app's inner core window (its frame is kept), not the shell's desktop windows; windows the application cloaked are dropped; windows the shell cloaked because they are on another virtual desktop are kept only when the user's Alt+Tab setting shows all desktops and the documented virtual desktop manager says they are elsewhere. Pane's own windows and windows with an empty title are dropped.
- **Records:** an opaque id valid for the session, title, application name and icon (the window's own AppUserModelID first, which separates web apps from their browser and finds Store apps hosted by the frame process; then the program's path matched against the "Applications done properly" specification (#124)'s applications; then the process's packaged identity), minimized, maximized, on another desktop, and whether it is elevated. Ordered by z-order with the front application first.
- **Activate:** restore if minimized, then the same foreground path as paste. A window on another virtual desktop is activated as Windows activates it from Alt+Tab; switching virtual desktops through undocumented interfaces is out of scope.
- **The default extension** "Switch Windows" lists them; typing filters by title and application name through the list's host filtering (the "Extension UI you can design" specification (#121)), or, until then, through its command search. Window actions (close, minimize, maximize, restore, keep on top) are a later slice using the "Extension commands like Raycast" specification (#120)'s action panel; an action refused because the window is elevated says so.

### System commands

- **Host capability** `pane:extension/system`, any command may use it, Windows implementations in this specification. **Default extension** "System Commands": each command is a no-view command (ADR 0037) that calls the capability and answers through ADR 0037's host functions (a HUD of the resulting state; a confirm dialog, destructive in style with "don't ask again", before Restart, Shut Down, Log Out and Empty Recycle Bin, kept for these as Raycast keeps it).
- **Catalog and mechanisms** (all documented Windows APIs):
  - Lock Screen; Log Out (planned shutdown reason, not forced, as in Raycast); Restart and Shut Down (enabling the shutdown privilege for the call only, and forcing applications closed, as Raycast does: the user's decision, ADR 0040, after the confirmation above);
  - Sleep: on a Modern Standby computer, turns the displays off so Windows enters its standby, otherwise suspends; Hibernate: only with a hibernation file, else explained;
  - Turn Off Displays (a monitor-power message to a window of Pane's own with a timeout, never a broadcast that a hung application could block); Start Screen Saver;
  - Volume Up, Volume Down, Toggle Mute, Set Volume (one argument, 0 to 100, through the "Extension commands like Raycast" specification (#120)'s typed arguments), on the default output device;
  - Toggle Microphone Mute: if any capture device is unmuted, mute all, otherwise unmute all; devices that vanish meanwhile are skipped; no microphone is explained;
  - Open Recycle Bin; Empty Recycle Bin (an already empty bin is a success);
  - Toggle System Appearance (the personalization values for apps and system, followed by the setting-change broadcasts with a hang timeout);
  - Toggle HDR (the display configuration's advanced colour state: if any capable display is off, turn all on, otherwise all off; none capable is explained);
  - Show Desktop; Toggle Hidden Files (and refresh open Explorer windows); Eject Removable Drives (each drive locked, dismounted and ejected, per-drive failures reported); Toggle Bluetooth (the documented radios API).
- **Left out:** Night Light, Airplane Mode, Energy Saver and the default audio device, which need undocumented interfaces; they may come later behind best-effort errors.
- **Other systems:** the package declares `windows`; Lock, Sleep, Volume and others exist on macOS and Linux and are proposed follow-ups, after which the package and each command list the systems they support (platform availability).

### Run

- **Host capability** `pane:extension/run`, Windows only, and **default extension** "Run".
- **History is Win+R's own:** read in Explorer's format (the lettered values in the order its list names, Explorer's trailing marker stripped, duplicates removed ignoring case); after each successful run, written back the same way with the new entry first, case-insensitive duplicates removed and at most 26 entries, so Win+R sees Pane's runs and Pane sees Win+R's. Delete from history rewrites the key without the entry. A failed run, or one declined at the elevation prompt, is not recorded.
- **Parsing:** a quoted head is taken as written; a head ending in a program, applet or console extension splits there; otherwise, for a rooted path with spaces, the longest space-separated prefix that exists on disk is the program (so unquoted paths with arguments work); otherwise the first space splits. Environment variables are expanded in both parts. Rooted paths are normalized (drive letter case, real casing, separators, network paths kept).
- **Running:** a `.cpl` applet through the Control Panel program; a bare name resolved on the search path read from the registry (machine and user), not Pane's own environment, and App Paths, so tools installed after Pane started are found; everything else (programs, documents, folders, network paths, `shell:`, `ms-settings:` and other registered schemes) through `ShellExecuteEx`, which also opens a folder in Explorer. "Run as administrator" uses the elevation verb, which shows Windows' prompt (ADR 0033).
- **Run in terminal** runs the command line through ADR 0033's run-program host function: in a new Windows Terminal tab when it is installed, otherwise in the shell's own window, with the shell (PowerShell, Command Prompt) chosen in the command's preferences.
- **Completions** while typing: Run history first, then programs from App Paths and the registry search path, Control Panel applets, management consoles, registered URL schemes and environment variables, each matching the typed text.
- **Shape:** Run uses command search today (its search field holds the command line; the first row is "Run “…”"), and is a query-taking command, so it can be a fallback and used through an alias. The "Root search like Raycast" specification's inline arguments and Tab may later give it Raycast's "Tab from root search".

### UI Access helper (later slice, flagged)

- A small helper program of Pane's own with `uiAccess` in its manifest, through which the hook, injected input and foreground changes reach applications running as administrator. Windows grants UI Access only to a program signed with a trusted certificate and installed in a protected location (Program Files or the system folder). Pane today installs per user under the user's local application data and signs nothing, so this slice needs a per-machine install option and code-signing credentials first; both are prerequisites outside this specification. Raycast's optional SYSTEM service that starts its helper elevated is not proposed.

### Packaging and contract

- Three new default extensions (Switch Windows, System Commands, Run), each declaring `windows`, enabled by default and each disableable on its own in Manage extensions: the user's decision, recorded in ADR 0040, which extends the five #60 recorded. They are acquired from Pane's artifact source like the others; an existing installation gains them as it gains any default extension it never had, and one the user uninstalled is not acquired again. Each joins the set when its slice lands. Proposed (ADR 0040): only the Windows default set lists them. The fourth extension ADR 0040 adds, Windows Settings, belongs to the "Applications done properly" specification (#124).
- New host imports: `windows`, `system`, `run`, plus the front application and selected-text host functions (through the "Extension commands like Raycast" specification (#120)'s contract) and the Windows implementation of ADR 0037's paste. JavaScript and TypeScript commands import them as they import `files` or clipboard history, through an opt-in in their package configuration; samples in Rust, JavaScript and TypeScript exercise each.
- Glossary additions through domain modeling: keyboard hook, game mode, front application, selected text, system command, Run history.

### Slices

1. The hook adapter with its safeguards, the refused-falls-back rule, and the record's new version (chords only).
2. Lone taps, double taps, sides and the extended key set, with hook recording, "Use the Windows key", "Show the taskbar when Pane opens" and the Windows key as the fresh-install default (ADR 0039).
3. Front application tracking and paste (needs the "Extension commands like Raycast" specification (#120)'s paste host function, ADR 0037).
4. Selected text.
5. Switch Windows (list and activate; actions later with the "Extension commands like Raycast" specification (#120)).
6. Run.
7. System Commands (needs the "Extension commands like Raycast" specification (#120)'s no-view mode, HUD and confirm, ADR 0037).
8. Game mode.
9. UI Access helper (later, flagged; prerequisites above).

## Testing Decisions

- **What a good test is:** it observes behaviour (a binding fires or not, what reached a test-owned window, what a command answered, what was written to a history the test owns) through the highest seam, never the hook's internal state or a registry layout beyond Explorer's documented format. Tests never lock, sleep, shut down, log out, change the user's appearance, empty the user's Recycle Bin or touch the user's own Run history.
- **Pure logic, on every system:** the binding recognizer driven by synthetic key-event sequences (taps, double taps within and beyond the window, sides, chords, keys between, stuck modifiers resynchronized, tagged events passed through, Start-menu masking emitted, coexistence refusal); binding record parsing and display; the window predicate over synthetic window attributes; window-to-application resolution over fake applications; Run's parser, normalizer, classifier and MRU rebuild; the system commands' decisions over fake capabilities (Modern Standby, no hibernation file, no HDR display, two microphones one muted).
- **Launcher public interface,** extending the existing hotkey tests with their fake adapter and real sample guests: a refusal by the system falls back to the hook and is reported as such, not as an error; still-refused shortcuts and coexistence are explained; a no-view command's hotkey runs it without a screen (ADR 0037); records of version 1 are read; a fresh data folder gets the Windows key alone as the Open Pane hotkey on Windows (Ctrl+Alt+Space when the fake hook cannot be installed), while an existing settings record keeps its hotkey; kinds unavailable on the test binary's own system are explained there; game mode pauses and resumes through a fake foreground source. With fake `windows`, `system` and `run` adapters and the real default extensions: Switch Windows lists and activates; each system command calls the adapter and answers with the expected HUD text, the destructive ones confirming first, Restart and Shut Down asking the adapter to force applications closed and Log Out not; Run runs, records, refuses to record a declined elevation, and deletes from history. The host functions (front application, paste, selected text) through samples in Rust, JavaScript and TypeScript against a fake system.
- **Window tests:** the recorder shows "Win", "Right Ctrl" and "Ctrl Ctrl" from a fake recording session; Escape still cancels; a hotkey row shows its dispatch route.
- **Windows adapters,** opt-in like the clipboard adapter test (a new `PANE_TEST_REAL_INPUT=1`, set by CI's Windows runner where its session allows input): the hook reports a lone Windows-key tap, a double tap and a side-specific chord injected with a test tag distinct from Pane's, and the Start menu mask is emitted; removing the hook behind the adapter's back is detected by the watchdog and repaired; paste into a test-owned edit control arrives, the clipboard is restored and a clipboard listener sees only tagged writes; selected text is read through UI Automation from a test-owned edit control, and through the simulated copy from a test window without a text pattern; the window predicate keeps a test's ordinary window and drops its tool, owned, no-activate and cloaked windows, and activation brings the test's window to the front; Run reads and writes Explorer's format in a test-owned registry key given to the adapter, resolves a program from a test search path, and runs a marker-writing test program; the system adapter is exercised only for reversible reads (volume, microphone state, HDR capability, Recycle Bin size).
- **Native smokes:** the hotkey phase gains a hook-dispatched binding (a shortcut the smoke registers first from another process, then assigns in Pane, pressing it to open Greeting), and a Switch Windows phase switches to a window the smoke opened.
- **Not provable in CI:** Start-menu suppression on a real desktop, game mode against a real game, the feel of lone and double taps, paste into elevated or hung applications and foreground reliability; these go to a ready-for-human check on a Windows 11 desktop, as the research's open questions list.

## Out of Scope

- Hotkeys on macOS and Linux beyond the extended key set (modifier taps and double taps there), hyper key, push-to-talk, snippets and text expansion.
- Virtual desktops (switching, moving windows, creating), Snap layouts and window layouts, move and resize by numbers, cycling an application's windows.
- Night Light, Airplane Mode, Energy Saver and the default audio device (undocumented interfaces); a volume mixer.
- Paste of images and files, paste sequentially, and Explorer's selected files.
- Running Pane's helper elevated through a service; any change to Pane's install location or signing (prerequisites of the flagged slice, not part of it).
- Script commands (decided later, ADR 0033).
- Paste, selected text, Switch Windows, System Commands and Run on macOS and Linux (explained as unavailable; follow-ups proposed above).

## Further Notes

- Research: `docs/research/raycast-deep-dive.md` (Windows integration), with the detailed input and system notes it summarizes. Raycast for Windows dispatches a binding through `RegisterHotKey` whenever Windows accepts it and through a low-level keyboard hook for everything else, including refused shortcuts, the Windows key alone (its fresh-install default), double taps, side-specific modifiers and layout-independent keys; it guards the hook with a raw-input liveness watchdog, locked hook pages, a high-priority thread, stale-modifier resynchronization and tagged injected input, and runs the hook in a UI Access helper so it also works over elevated windows. Its paste tracks the previous foreground window excluding shell surfaces, waits for the target to be in front, writes the clipboard tagged against history and restores the user's clipboard unless it changed; its selected text uses UI Automation in a worker process with a 2.5 s timeout and falls back to a simulated copy; its Run shares Win+R's RunMRU in Explorer's format; its system commands use documented APIs except Night Light, Airplane Mode, Energy Saver and the default audio device. Pane takes these behaviours, not Raycast's code.
- ADRs: 0001 (small core), 0002 (trusted extensions), 0014 and 0033 (programs an extension runs; Run in terminal and elevation use ADR 0033's host function and prompt), 0015 (the host capability pattern followed by `windows`, `system` and `run`), 0016 (amended by ADR 0039 for the hook fallback and the fresh-install default, and by ADR 0037 for no-view hotkeys), 0020 (clipboard history, which ignores Pane's tagged writes), 0035 (HUD and toast durations), 0037 (no-view mode, HUD, confirm, paste), 0039 (hotkeys fall back to a keyboard hook, a refused shortcut is no longer an error, and the Windows key opens Pane on a fresh install), 0040 (the new default extensions, enabled by default; Restart and Shut Down forced).
- Today Pane's own clipboard write-back (copying a history item again) carries no markers, so Windows' history keeps it; ADR 0037's concealed copy and this specification's tagging should be applied there too.
- The global hotkeys documentation still says Pane has no summon hotkey; the "Quick fixes" specification (#129) fixes that statement for what ships today, and this specification's documentation changes (the Windows-key default, the hook fallback) build on that correction rather than repeat it.
