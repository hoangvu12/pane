## 1. Selection and hover drawing

### The one place the wash tokens live: `crates/pane/src/ui/theme.rs`

`Theme` (struct at ~L60) holds every selection value as a semantic field; `Theme::dark()` (~L1040) and `Theme::light()` (~L1140) are the palettes:

| Token (field) | Dark (`0xRRGGBBAA`) | Meaning |
|---|---|---|
| `row_hover` (~L124) | `0xFFFFFF09` = white **3.5%** | row under pointer (unselected) |
| `row_selected` (~L126) | `0xFFFFFF16` = white **8.5%** | selected row wash |
| `row_selected_border` (~L128) | `0xFFFFFF0D` = white 5% | selected row's 1px inset edge |
| `action_selected` (~L264) | `0xFFFFFF1C` = white **11%** | Actions panel / Pane menu entry |
| `control_hover` (~L267) | `0xFFFFFF0F` = white 6% | footer buttons + panel/menu hover |
| `nav_selected` / `nav_hover` (~L204) | `0xFFFFFF17` / `0xFFFFFF0D` | Settings sidebar + Extensions rows |
| `slot_background` / `slot_edge` / `slot_hover` (~L292) | `0xFFFFFF09` / `0xFFFFFF0D` / `0xFFFFFF12` | pinned slots |
| `footer_button_open` (~L268) | `0xFFFFFF1A` | Actions button while panel open |
| `focus_ring` (~L157) | `0xFFFFFF80` = white 50% | keyboard focus ring |

Light palette flips washes to black (e.g. `row_hover 0x0000000B`, `row_selected 0x00000016` at ~L1165). `pressed(wash: Hsla) -> Hsla` (L37–53) doubles a wash's alpha (≤1) or darkens opaque ones; every press state derives from its hover/selected wash through it. **Over a background image**, `Theme::over_backdrop(canvas)` (~L1280) overrides: `row_hover = wash(0.06)`, `row_selected = wash(0.10)` (plain white/black wash), `row_selected_border = frost.edge + 0.01 alpha`, and installs `Theme::frost: Option<Frost>` (struct ~L1340: `blur 30px`, `tint` canvas@40%, `edge`, `top`, `label` ink, pill metrics; `Frost::edges()` returns the 1px ring + top line shadows).

### Each surface

- **Root search rows** — `crates/pane/src/ui/result_row.rs`, `row_surface()` (L325–345): unselected → `.hover(|row| row.bg(theme.row_hover))`; selected → `backdrop_blur(frost.blur)` when `theme.frost` is set (ADR 0028 frost), `.bg(theme.row_selected)`, and the **1px inset edge** as `BoxShadow::new(0,0,row_selected_border).spread_radius(1).inset()`. `pressed_wash(selected, theme)` (L305) is attached by the app after the row's id (`.active(...)` in `LauncherWindow::render_row`, `crates/pane/src/app.rs` L1349, press at ~L1461). A selected row keeps its wash under the pointer (no hover swap). Root rows also select under a *moving* pointer: `pointer_moved_over` (app.rs L1300) / `click_root_row` (L1332). `with_number_hint` (L292) wraps rows/slots with `keycap::row_number_hint`.
- **A command's list / command search** — the same `result_row_with` via `render_row`; a command's rows do *not* select under the pointer (click selects+runs); only root rows get `on_mouse_move`.
- **Computed answer card** — `crates/pane/src/ui/result_layouts.rs`, `answer_card()` (L120): fill `theme.results.card_fill` (white 6%), and **while selected a 1px inset ring in the accent**: `.when(card.selected, |s| s.shadow(vec![ring(theme.accent_text)]))` (L188–190; `ring()` L331). Press = `pressed(results.card_fill)` (app.rs `render_answer` L1488).
- **Confirmations** — `crates/pane/src/features/confirmation.rs`, `render_confirmation_layer` (L236): no selectable rows; its buttons are `ui/footer.rs` `footer_button(..., ButtonWash::Hover, ...)`; dialog surface is `Material::popover` + `popover_shadows`, over a dimmer `bg(theme.actions_dimmer)`.
- **Manage extensions (Settings)** — `crates/pane/src/features/settings/extensions.rs`: `sidebar_entry` (L711–760) — selected `nav_selected`/`nav_selected_text`, hover `nav_hover`, press `pressed(hover)`; the enable/auto-update switch rows use `.hover(|row| row.bg(theme.nav_hover))` (~L1299). The Settings sidebar's shared version is `crates/pane/src/ui/settings_shell.rs::sidebar_item` (L241–310). Settings' own "settings rows" use `ui/controls.rs` (`nav_hover` at ~L687/838, `setting_row`).
- **Actions panel** — `crates/pane/src/features/actions_panel.rs`, `action_row()` (L1439): `.when(selected, |row| row.bg(theme.action_selected))` (L1476); `.when(!selected && available, hover control_hover)` (L1478); press `pressed(action_selected|control_hover)` (L1481). Panel = `Material::popover`, anchored `actions_geometry` (width 320, inset 10, 8 above footer) via `anchored()` (L1695).
- **Pane menu (footer menu)** — `crates/pane/src/features/footer_menu.rs`: entries reuse the `.arow` family — `action_selected` when selected, `control_hover` on hover, `pressed(...)` while held (`menu_list`, ~L383–465). The menu button (`render_menu_button` L267) is `footer::mark_button` + `control_hover` hover / `footer_button_open` while pressed, and a **1px inset `focus_ring` via `.focus(...)`** (L335–341).
- **Pinned slots** — `crates/pane/src/ui/pinned.rs`, `pinned_slot` (L161): `slot_background` + `slot_edge` 1px inset (or `frost.edges()` + `backdrop_blur` over a picture), `slot_hover` on hover, `pressed(slot_hover)`; **keyboard focus** draws the reference's 2px inset outline: `.focus_visible(|slot| slot.shadow(...focus_ring...spread_radius(focus_width)))` (L178–186, `PinnedGeometry::focus_width = 2`).

- **Compact pins** — `crates/pane/src/features/compact_pins.rs::render_compact_pin` (L144): 34px square, `row_hover` hover (L157), `pressed(row_hover)`, radius 9; geometry constants local to the file (`ROW_HEIGHT 48`, `PIN_SIZE 34`, `PIN_RIM 3`, `PIN_GAP 4`).
- **Footer buttons** — `crates/pane/src/ui/footer.rs`: `footer_button` (L81) with `ButtonWash` (L62): `Hover` = `control_hover` on hover + `pressed` while held; `Pressed` = `footer_button_open` + `footer_button_open_text` (Actions button open); `None` = no hover. `divider` (L168) is the 1×16 `footer_divider` rule.

### Focus rings — where they come from

Rows and list items draw none (focus stays in the search field/list; the announcer speaks the selection). Rings are drawn only by controls that take the keyboard: `pinned_slot` (2px inset, `focus_visible`), the footer-menu button and toast action buttons (1px inset `focus_ring`, `.focus(...)` in `footer_menu.rs` L335 and `toast.rs` `toast_buttons`), Settings controls (`ui/controls.rs` segment focus shadows, `ControlGeometry::focus_width = 2`; `features/settings/appearance.rs` L439/L585 `focus_visible` ring), and the select's boxed field (`ui/select.rs`). ADR 0035: these survive; the row edge and answer-card ring go.

### Motion policy and reduced motion — `crates/pane/src/ui/motion.rs`

One policy module (read its full doc header): constants `VIEW_ENTER 100ms`, `SECTION_ARRIVAL 150ms`, `DISCLOSURE 180ms`, `POPUP_ENTER 140ms`, `POPUP_EXIT 100ms`, `VIEW_SHIFT 3px`, `VIEW_OPACITY_FLOOR 0.3`, `REVEAL_IN 160ms`, `REVEAL_OUT 120ms`; one `Tween` type measured on `App::background_executor().now()` (deterministic under the test clock); entry points `advance` (view transitions), `advance_arrival`, `advance_disclosure`, `advance_reveal` (number hints), `advance_popup` (+`PopupMotion`), wrappers `arriving`/`arriving_page`. **Hover/press washes never animate** ("changes at once" — see the module docs and the test asserting `settle_frames == 0` after a hover, `tests/launcher_settings.rs` ~L2159). The window's per-frame driver is `crates/pane/src/app/frame_motion.rs::FrameMotion::frame` (L145–215; also owns the menu-popup tween and `Numbers` reveal state, and `frame.animating` → `window.request_animation_frame()` in `app.rs::render`). Reduced motion: `observe_reduced_motion` (motion.rs L576) sets `App::reduce_motion` from `UISettings.AnimationsEnabled` on Windows (fail-closed; watched via `AnimationsEnabledChanged`), full-motion fallback on macOS/Linux; `PANE_TEST_REDUCE_MOTION` env override in debug builds; `PANE_MOTION_SCALE` stretches timelines for native captures. Tests flip it with `cx.update(|_, cx| cx.set_reduce_motion(true))` — worked example: `tests/window.rs::reduced_motion_settles_transitions_at_once_without_frames` (L3114–3145).

## 2. Theme and text — `crates/pane/src/ui/theme.rs`, `ui/contrast.rs`

`Theme` is the single token file ("every value is stated by role… restyling is a one-file edit"). Key groups:

- **Text roles** (~L45–60): `text_title` (row titles, footer's command lead, HUD title, panel base ink set in `app.rs::render` via `.text_color(theme.text_title)`), `text_body` (body copy: details lines, confirmation message, toast message, status colors), `text_muted` (subtitles, kind labels, section labels, footer hint, placeholder's sibling), `text_query` (typed query), `text_placeholder` (search/filter placeholders), plus per-surface labels: `keycap_text`, `footer_button_text`, `action_text`, `slot_title`, `nav_text`/`nav_*_text`, `alias_text`, `tile_foreground`, `frost.label` (section labels over a picture — `ui/shell.rs::section_label` L60 picks `frost.label` when frost is set).
- **Surfaces** are themed in `crates/pane/src/ui/material.rs`: `Material::panel` (L1 glass = `panel_tint` over the compositor frost; `Opaque` = `panel_solid`), `Material::settings_panel` (`settings_tint` .78), `Material::popover` (L2 `popover_tint` + in-scene `backdrop_blur(30)` in glass; `popover_solid` otherwise; inset edges `popover_edge`/`popover_top_highlight`; outer shadows via `popover_shadows()`), `Material::footer` (`footer_tint`, top rule `hairline_soft`, frosted over a picture). `Material::new` normalizes `Glass`→`Opaque` when `glass_fallback_reason()` says the platform can't blur.
- **Separators**: `hairline` (panel inner edge, material.rs `inset_edges`), `hairline_soft` (search-header bottom border `root_search/mod.rs::search_header` ~L285; footer top rule), `footer_divider`, `action_rule` (Actions panel separators + search rule), `card_rule`, `popover_edge`.
- **Disabled**: no dedicated ink token — `ControlGeometry::disabled_opacity = 0.4` for Settings controls, `.opacity(0.5)` for unavailable action rows / action buttons / slot tiles.
- **Typography** (`Typography::shared()` ~L1364): Geist/Geist Mono, `search_size 19`, `row_title_size 14`, `row_subtitle_size 13`, `row_kind_size 12.5`, `footer_size 12.5`, `keycap_size 11` (compact 10), `section_size 12` (+tracking .01em), `action_size 13`/450, `slot_title_size 12.5`, results/settings type structs. All text-role consumption sites are listed on each field's doc comment — those comments are the consumption map.
- **Light palette** is derived (theme.rs L1134 header); `over_backdrop` steps `text_muted`/`text_placeholder` up a shade over a picture.

**Contrast — `crates/pane/src/ui/contrast.rs`** (105 lines): WCAG helpers `GRAPHIC = 3.0` (L15), `TEXT = 4.5` (L18), `luminance`, `ratio`, and `corrected(color, surface, needed)` (L43) which lightens/darkens a colour until it meets the ratio, keeping hue and alpha. Used by `crates/pane/src/features/icons.rs::color` (tints/accessories corrected against `theme.panel_solid`; accessories to `TEXT`, icons to `GRAPHIC`). Unit tests live in-file (`mod tests` L67: keeps a readable colour, fixes one that isn't, exact 21:1 black/white). **The "glass tint legibility floor" is not code**: the 55%-alpha floor is a documented claim only — `theme.rs` field doc on `panel_tint` (~L87: "Legibility floor: the reference keeps the tint at or above 55% alpha") and the module header's "contrast honesty" paragraph (~L20–35, dark .7 tint over white ≈ #5c5d5f, muted ≈ 2.04:1, title ≈ 5.64:1 — explicitly *not* a guarantee). Nothing enforces or tests a tint floor; `contrast.rs` corrects *extension-chosen* colours, not Pane's own roles. Other in-file unit tests for area 2: `ui/result_layouts.rs` (`mod tests` ~L340: value-column widths, type step-downs). `theme.rs` itself has **no** test module; token values are verified through window tests (`paints_fill_at`, e.g. `tests/launcher_settings.rs` L2153–2196 asserts `0xFFFFFF16`, `0xFFFFFF1C`, `0x0000003D`, `0xFFFFFF1F`) and native screenshot checks (`scripts/check_screenshot.py` — `selected` requires a broad wash, `answer` checks the accent ring).

## 7. Keyboard

- **Window layer — `crates/pane/src/keyboard.rs`**: `bind_keys` (L53) registers each `pane_core::KeyboardAction` under its effective binding (`Binding::id()` string grammar, e.g. `"ctrl-enter"`), in the `Launcher` context (`KEY_CONTEXT`, app.rs L65) plus the field context `"RootSearch > EditableText"` for the selection keys; `rebuild` (L123) clears and re-makes the whole keymap on change. **`binding_of(&Keystroke) -> Result<Binding, String>`** (L133) converts a real key press into a `Binding` using *all* modifiers and `keystroke.key` — this is the chord-matching primitive. `binding_keys` (L196) → keycap `KeySequence`; fixed keys: `quick_slot_binding(number)` = `ctrl-<n>`, `toggle_pin_binding()` = `ctrl-shift-f`, `move_pin_bindings(earlier)` = `ctrl-alt-{up,left}`/`{down,right}`, `escape_keys()`.
- **Core — `crates/pane-core/src/keyboard.rs`**: `KeyboardAction` (8 actions, `ALL`), `Binding` (modifiers+key, `parse`/`id`/`protected` — text-editing/typing keys are refused for rebinding), `Keyboard` (defaults, record round-trip, `checked_set`/`check` collision rules), fixed keys `pin_key` (L623), `move_pin_keys` (L633), **`toast_key()`** (L645, `ctrl-t`/`cmd-t`), `number_key` (L651, `ctrl-0..9`), **`action_key(index)`** (L659: index 1 = `ctrl-enter`, 2 = `ctrl-shift-enter`, else `None` — the Enter variants for item actions), and `PaneKeys` (L678: every key an extension shortcut may never take). Defaults: up/down/enter/escape, `shift-escape` return-to-root (macOS `cmd-escape`), `ctrl-w`/`cmd-w` dismiss, `ctrl-,` settings, `ctrl-k` open actions.
- **How chords match modifiers today**: everywhere in Pane, comparison is **exact `Binding` equality** (all modifiers + key): `LauncherWindow::item_action_keys` (app.rs L550–590: `pressed == invoke` → first action; `action_key(1..=2)`; else `actions.bound_to(&pressed)`), `toast_action_keys` (toast.rs L304), `ActionsPanel::panel_keys` (actions_panel.rs L866, `pressed.id() == "enter"` for its own Enter), `quick_slot_chord` → `chord_digit` (quick_slots.rs L114: `(1..=9).find(|n| quick_slot_binding(n) == pressed)`). Proof in tests: `crates/pane/tests/item_actions.rs::an_actions_shortcut_runs_it_from_the_list` (L135 — "Not the same modifiers: nothing runs": `ctrl-c` does not run `ctrl-shift-c`) and `docs/list-tree.md` L148 ("Modifiers match exactly"). **The one place extra modifiers can still trigger a plainer chord** is the GPUI keymap itself (fork `gpui-ce @ 5d27954`, `crates/gpui/src/platform/keystroke.rs::Keystroke::should_match`): after the `key_char` special cases — on Windows a keystroke whose `key_char` differs from `key` matches a **modifier-less** binding of that `key_char` (the AltGr case, since Windows reports AltGr as ctrl+alt); on other platforms it matches a `ctrl+platform` binding — matching falls back to `target.modifiers == self.modifiers && target.key == self.key` (exact). `binding_of` reads `keystroke.key`, never `key_char`, so Pane's own chord handlers never fire on the AltGr form; only keymap-dispatched bindings can.
- **Ctrl+digit, number hints, the 400 ms hold** — `crates/pane/src/features/number_hints.rs`: `NUMBERS_HOLD = 400ms` (L26); `Numbers { shown, pending, generation, reveal }`; `modifiers_changed` (L99, wired on the window root in `app.rs::render` L2027) starts the hold only when Ctrl is held **alone**; any other modifier ends it (`end_numbers`); a key press while pending cancels the look (`chord_pressed`, called from `quick_slot_chord`). The chord is read from the key press itself in capture phase (`on_quick_slot_keys` → `quick_slot_chord`, quick_slots.rs L434–462) so auto-repeats are told from presses via `event.is_held`. The hints' slide is `motion::advance_reveal` through `FrameMotion::numbers`.
- **Pin keys** — quick_slots.rs `bind_keys` (L89): `PressSlot` (enter/space) in `QuickSlot` context, `TogglePin` (`ctrl-shift-f`) in the Launcher context, `MovePinEarlier/Later` in `QuickSlot`.
- **Keyboard page and rebinding (#77)** — `crates/pane/src/features/settings/keyboard.rs`: recorder rows (`KeyboardControl::Recorder`), `keyboard_key_down` (L656) records `binding_of(keystroke)` through `keyboard_apply` (L680) → `settings.set_keyboard` → `crate::keyboard::rebuild`; protected/collision refusables come from core `Binding::protected`/`Keyboard::check`; Escape behavior segments, escape-closes switch, navigation-bindings select (Emacs/Vim: Alt+N/P etc.). The command *hotkey* page (global, system-registered) is `features/settings/shortcuts.rs` (`shortcuts_hotkey_key_down` L641). Tests: `crates/pane/tests/keyboard.rs` (rebind takes effect at once, persists, survives restart; chords shown/pressed whole — `a_chord_on_the_invoke_action_is_shown_announced_and_pressed_whole` L291).
- **AltGr**: nothing in Pane names it; the behaviour that exists is the fork's `should_match` key_char path above (plus `Binding::protected` refusing platform editing chords like `ctrl-c` for rebinding).
- **Ctrl+C today**: no launcher-wide binding. In a focused text field it is the editable element's own copy (protected from rebinding by `Binding::protected` → "copies"). Pane's own copies: Enter on a copyable row (`app.rs::activate_selected` L1108: `launcher.selected_copy()` → `cx.write_to_clipboard`), the Extension Logs screen binds `ctrl-c`/`ctrl-shift-c` (`features/extension_log.rs::bind_keys` L81: CopyLine/CopyAllLines), Clipboard History's copy is the `ctrl-enter` action chord (`features/clipboard_history.rs::copy_binding` L129), and a toast's "Copy Error" action copies in `choose_toast_action`.

## 8. The window-test harness (`crates/pane/tests/`)

- **`tests/window.rs`** (~4,630 lines) is the model: `open_launcher` (L112) does `cx.executor().allow_parking()` (guest replies arrive on real runtime threads), `cx.update(pane::bind_keys)`, `cx.add_window_view(|window, cx| LauncherWindow::new(...))`. Samples are registered, not built-in (#162): `support/samples.rs::sample_commands()` loads `target/guests/{sample_rust,sample_js,sample_ts}.wasm` (built by `cargo xtask guests`) as `CommandRegistration`s; `support/packages.rs` writes/copies assembled packages (`pane.json` + wasm) for `launcher.install_package(...)` (blocked on the foreground executor); icons tests install `target/guests/packages/<sample>` folders; fake application icons go through `Launcher::with_application_icons(folder, extractor)`.
- **Pressing real keys**: `cx.simulate_keystrokes("ctrl-shift-enter")` (modifier grammar as in `Binding::id()`), `cx.simulate_input("text")` for typing, `cx.simulate_keystrokes("tab down enter")` sequences. **Auto-repeat**: dispatch a raw event — `cx.simulate_event(gpui::KeyDownEvent { keystroke: Keystroke::parse("ctrl-1").unwrap(), is_held: true, prefer_character_input: false })` (`tests/item_actions.rs` L167–180; `tests/window.rs` L4433). Double clicks likewise via raw `MouseDownEvent/MouseUpEvent` with `click_count: 2`.
- **Pointer**: `cx.simulate_mouse_move(point, None::<MouseButton>, Modifiers::none())`, `cx.simulate_click(bounds.center(), Modifiers::none())`, `simulate_mouse_down/up`; positions come from `cx.debug_bounds("<debug_selector>")`. "Pointer leaves" = move to `point(px(-100.), px(-100.))` (`tests/feedback.rs::pointer_leaves` L148).
- **Controlled clock/animation**: `cx.executor().advance_clock(Duration)` (toast countdowns, the 400 ms hold, announcer `SETTLE`); `support/wait.rs::frame(cx, elapsed)` (L41) advances the clock then delivers one animation frame (`window.simulate_next_frame`), returning how many callbacks ran (0 = window idle); `settle_frames(cx)` (L55) delivers 25 ms frames until none is requested (bounded). `cx.run_until_parked()` drains background work.
- **What is drawn**: `support/paint.rs::paints_fill_at(cx, bounds, 0xRRGGBBAA)` (L9) checks the last frame's `window.painted_quads()` for a fill at bounds in that colour — this is how washes/hex values are asserted (e.g. `tests/launcher_settings.rs` L2153–2196).
- **Announcements**: `support/a11y.rs` — `a11y(cx)` forces the accessibility tree on and returns `debug_a11y_tree_json()`; `announcement(cx)` reads the announcer Label node's name (== value); `focused_label`, `no_row_has_focus`.
- **Waiting for the view**: `support/settle.rs` — `settle` (status not Running *and* drawn), `settle_bare` (also nothing drawn over), `until(view -> bool)`, `settle_shown` (maps the footer toast back to a `Status`), `enter_flow`. Window state is read through the `#[doc(hidden)]` methods (area header).
- **Sibling suites to imitate**: `tests/keyboard.rs` (Keyboard page, two windows), `tests/compact_pins.rs` (compact geometry), `tests/command_search.rs` (a command's own search field; local `Service`), `tests/feedback.rs` (toast/HUD timing), `tests/announcements.rs` (announcer with clock), `tests/item_actions.rs` (chords + held keys), `tests/confirmations.rs`, `tests/icons.rs` / `default_icons.rs` / `application_icons.rs` / `web_icons.rs` (area 3).

**Worked example — `crates/pane/tests/feedback.rs` L157–183 (timing, clock, pointer, debug bounds):**

```rust
#[gpui::test]
fn a_toast_shows_in_the_footer_and_a_success_leaves_after_three_seconds(cx: &mut TestAppContext) {
    let (window, cx) = opened(cx);
    pointer_leaves(cx);
    cx.simulate_keystrokes("enter");
    assert_eq!(settle_shown(&window, cx), Status::Result("Open: Alpha note".into()));
    assert!(cx.debug_bounds("status-toast").is_some(), "the footer's toast");
    assert!(cx.debug_bounds("toast-success").is_some());
    wait(Duration::from_millis(2900), cx);
    assert!(toast(&window, cx).is_some(), "still there before 3 seconds");
    wait(Duration::from_millis(200), cx);
    assert!(toast(&window, cx).is_none(), "gone after 3 seconds");
}
```

(with `fn wait(time, cx) { cx.executor().advance_clock(time); cx.run_until_parked(); }` at L143, and `the_pointer_over_a_toast_pauses_its_time` at L186 for the hover pause.)
