# spec/129 review findings to fix (one fix pass)

## #133 (diagnostics / crash record)
1. log.rs `rotate`: a failed rename(pane.log -> pane.1.log) is ignored; on Windows (second Pane, editor holding it) every later line re-rotates and shifts pane.N, deleting all older logs within 5 lines while pane.log grows unbounded. Fix: if the rename fails, do not shift/delete; back off (e.g. retry rotation only after more bytes or at next start) and never delete older files unless pane.log was actually moved.
2. Redaction is a plain substring match; user/computer names like "pane", "root", "admin", "localhost" mangle messages ("<user>istrator", every "Pane" -> "<user>"). Fix: match only at word/path-component boundaries (non-alphanumeric neighbours), keep case-insensitive and the >=3 chars rule; add tests for "pane"/"admin" not mangling ordinary words. Record the choice in the doc.
3. scripts/smoke-windows.ps1 `Stop-Pane` kills Pane with Stop-Process and restarts on the same data folder → later phases now see the "Pane quit unexpectedly" row and status line. Update the smokes (Windows, and check macOS/Linux smokes and measure scripts, incl. scripts/measure-linux.sh) so expected root rows/status account for it — e.g. remove stale markers in the logs folder before restarting, or quit cleanly. Do not run any script.
4. web-image privacy: `why.replace(url, &address)` only scrubs the exact URL string; build the message from host:port without including the error's URL text at all (or strip any URL-like substring).
5. Possible re-entrant deadlock: `begin_run` and `finish` take the log lock without setting the thread-local WRITING guard; set it there too.
6. Copy diagnostics includes the full log path with the user's name: redact it (home -> ~) the same way the log does.

## #130 (DPAPI)
7. Counts decrypt: `kept_now` → `DataJson::tally` calls `value.text()` on every protected value of every owner (uninstall confirmation uninstall.rs ~448, dependents, retained rows). Ticket: counts work "without decrypting anything". Fix: totals never decrypt; the "N unreadable" figure is computed only for the identity a Manage-extensions row describes (or lazily, once per open, cached).
8. `ExtensionData::remove`: `data.file = fresh` reloads from disk without `protect_plain_values`; if the start-up conversion failed, an uninstall/retained deletion writes other packages' tokens as {"plain": …} into a version-2 file. Fix: protect the reloaded file's plain values before writing (or keep version 1 if protection fails — never write plain values into a version-2 file on Windows).
9. `HistoryJson::to_json` aborts the whole clipboard write if one item fails to seal → nothing saved, deletions included. Fix: keep the item in memory unsealed-and-retried, write the others (an item that cannot be sealed is left out of this write with a diagnostic and retried next write — but never drop it from memory), or write it plain-marked; choose the safest and document.
10. guests/js/data.d.ts wording: "each value encrypted for the current user on Windows (DPAPI), as it is on macOS and Linux" reads as if macOS/Linux encrypt. Fix to match wit/data.wit. (data.d.ts is a prebuilt input; it is already stale — fine.)
11. The Launcher damaged-token test shows "other values still read" only for other kinds; add another credential key that still reads.

## #131 (tray)
12. Known concern confirmed: tray/windows.rs ~241 `set_visible` stores `self.wanted = visible` before trying and does not restore on error; settings.rs ~788-792 `set_tray_visible` returns on Err without re-syncing. Result: a refused show (preference rolled back to hidden) reappears at next TaskbarCreated; a refused hide leaves wanted=false with preference on, so the icon never returns after Explorer restarts. Fix on the application side: on Err in `set_tray_visible`, call `tray.set_visible(self.chosen.tray_visible)` again (resets wanted to the preference) — keep the sign-in case (show refused before the taskbar exists still appears at the first broadcast; test `a_show_refused_at_start…`). Add a unit test for the rollback case.
13. GUID test values use unprefixed paths but production canonicalize() returns `\?\C:\…`; make derivation strip the verbatim prefix (or test the prefixed form) so the test pins what ships.
14. `with_entry` drops a TaskbarCreated/theme broadcast arriving while the menu's modal loop holds the entry: queue it (set a flag and handle after the menu returns).
15. #182 doc: "the launcher's window stays open" when the Open Pane hotkey cannot be registered at start — no code found for it; verify against crates/pane and remove or correct.

## #132 (announcer)
16. Scope creep / bug: every footer message goes through the announcer (Running…, progress, results); each new message re-arms the 500 ms STATUS_LEAD, so a fast-changing progress line starves the selection announcement forever. Spec: "The footer's status strip stays a status live region"; toast first, then selection. Fix: only toasts (and status messages that are outcomes, not progress) lead; cap the wait (the selection is said at most ~500 ms after the move regardless of later status changes); progress updates do not re-arm.
17. Stale held text: `frame()` releases `held` when its time is up without checking the current list; if the panel closed, the list changed or typing started during the wait, an old row is spoken. Fix: re-derive the held text from the current selection at release time (or drop it if the list/context changed).
18. Root opens Silent and never clears `text`: if the live node is re-created, AccessKit announces on add (Windows: live node with name; macOS: value), speaking the last command's row on root. Fix: clear text when returning to root / on a context change, and keep the node's element id stable across the split-view render.
19. Over a form or custom view, closing the panel calls `frame(None)` so `follow` never clears `over`; reopening the same panel counts as `same` and its opening is never said. Also same-text-twice is silent (reopening footer menu). Fix: clear `over` on frame(None); when the same text must be said again, alternate a trailing invisible difference is NOT acceptable — instead clear the text for one frame before setting it again (document).
20. Non-root screens Confirm, Package, BuildDetails open as "<title>, n results" — use their own wording or say only the title where "results" is wrong.
21. Tests that cannot prove their claim: `several_fast_moves` sends "down down down" in one simulate call and reads once — send moves in separate frames/run_until_parked between them and assert the final text equals the last row and earlier texts never remained after the final frame; the "said once" check should count changes (e.g. record the announcer's text after each frame and count transitions). Toast-ordering test should use a real toast if any sample can show one with a selection change; else document. Add announcement checks for the footer menu and Clipboard History (focus stays, position/size, one Down), and "No results"/", unavailable" in a command's list.
