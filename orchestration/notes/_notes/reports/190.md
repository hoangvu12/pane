## Design

- **In flight.** Every request sent through `Shared::send` carries an `InFlight` guard (`Watch::call`). The channel now carries `Sent { request, in_flight }`. `Host::dispatch` moves the guard into the request's task, so it drops when the task completes, or when the task is dropped with the thread. Requests that finish at once (`Forget`, a closed view, `Quit`) drop it at the end of `dispatch`.
  - Covered: every kind of guest call, a view's destructor (`CloseView`), and host work that waits on guests (`Running`, `ViewCount`). They all go through `Shared::send`.
  - Not counted: the thread's own `DropStopped` nudge. It runs no guest code.
- **Waiting.** The `Polls` mutex holds three new fields: the call count, `ticker_waits` and `watchdog_waits`. `Watch.awake` is the new condvar. `Watch::wait(Timer)` checks and waits under that one lock, so a call that starts as a timer goes to wait still wakes it.
  - The ticker waits while `calls == 0` and the thread has not ended.
  - The watchdog waits while `calls == 0`, the thread is outside any poll, and it has not ended.
  - What wakes them:
    - `Watch::call` notifies if either timer waits.
    - `Watched::poll` notifies when the thread starts a poll while the watchdog waits.
    - `Watch::end` and `give_up` notify both.
- **The ticker** waits at the top of each loop. After waking it sleeps `TICK` and ticks, exactly as before. A woken end still gets its last tick.
- **The watchdog**, when idle, first says "carried on" (`slow(false)`) if it had warned: the thread was just seen outside any poll. It then waits, and on waking starts a fresh `Quiet`, so time spent waiting is not counted as quiet time. After that it sleeps `WATCH_EVERY`, looks, and gives up exactly as before.
- If the runtime thread itself fails to spawn, `spawn` now calls `watch.end()`, so the ticker does not wait for ever.
- **Debug hook:** `Runtime::timers() -> Option<Timers>` (doc-hidden, debug builds only). `Timers` holds `ticker_waiting`, `watchdog_waiting`, `calls`, `ticks` and `looks`. The two counters are atomics that are bumped in all builds and read only by the hook.

## Spec ambiguities resolved

- **"In flight" is per request, counted from the sender.** It is not counted at dispatch. If it were, a request queued behind a thread stuck while idle would never wake the watchdog. Counting at the sender also covers "host work that waits on a guest".
- **The watchdog also stays awake while the thread is inside a poll with nothing in flight.** The spec says "sleeps while nothing is in flight". Without this, a thread stuck while idle (the smoke's `inject hang` before Return) would be counted only from the next call, and the "not responding yet" check 4 s after Return could miss. With nothing in flight the thread polls only on a nudge or a fault, so this costs no wake-ups.
- **A warning said before the watchdog sleeps is withdrawn** (`slow(false)`): the thread was seen outside any poll, which already counts as progress. Without this, the status line could keep saying "not responding yet" while Pane is idle.
- **Watchdog wait time is not quiet time** (a fresh `Quiet` on waking), in line with `LOOK_GAP`'s "only time the watchdog saw counts".
- **The race test is a unit test with a core module, not a launcher test.** Repeated computing calls through the launcher would pause the sample after three. The samples that compute also need package data, which the public `Runtime` API cannot give.
