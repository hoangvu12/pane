## Unsure; check first when it first runs

1. **Windows hide.** The Escape is posted with `PostMessage` (`WM_KEYDOWN`/`WM_KEYUP`, `VK_ESCAPE`) to Pane's HWND. GPUI's message loop does route posted key messages: `translate_accelerator` → `WM_GPUI_KEYDOWN` → `handle_keydown_msg`. I could not confirm that GPUI dispatches the key to the focused query field while the window is not the foreground window. If the posted Escape does not hide Pane, the fallback types Escape with SendKeys, but only when Pane's window is the foreground window. Otherwise the run throws and nothing reaches another window.
2. **Windows sampler.** The x64 offsets were written from the known `SYSTEM_PROCESS_INFORMATION` (0x100) and `SYSTEM_THREAD_INFORMATION` (0x50) layouts and never executed:
   - process: CreateTime 32, UserTime 40, KernelTime 48, ImageName 56/64, pid 80, ppid 88, WorkingSetSize 144;
   - thread: CreateTime 16, UniqueThread 48, ContextSwitches 64.
3. **Closing Pane.** `WM_CLOSE` is posted to the hidden launcher window to make Pane quit. If it does not exit within 10 s, the script falls back to `Stop-Process`.
4. **Launch at login (a real hazard I found).** A scratch Pane with a fresh `settings.json` would delete the user's real `HKCU\...\Run\Pane` value: `reconcile_login` removes a registration the user did not choose. The script prevents this by pre-writing the scratch `settings.json` with `launchAtLogin` equal to whether the value exists. Afterwards it checks the value and puts it back if it changed.
5. **Linux hide.** It is `xdotool key Escape` on the focused launcher, and "hidden" means not `--onlyvisible`. I assumed GPUI on X11 unmaps on `set_visible(false)`.
6. **Linux requirement.** `measure-linux.sh` now requires `target/dist/artifacts/pane-defaults.json`. In CI's smoke job the earlier `smoke-linux.sh` step builds it. On-demand runs need `cargo xtask package-linux --dev` first. In CI those artifacts index a 99.0.0 application package, so the debug Pane may offer itself an update; nothing is downloaded.

## Spec ambiguities and how I resolved them

- **"Defaults only".** Real default extensions acquired through `PANE_ARTIFACTS` from `target/dist/artifacts`, the smoke's clipboard-phase pattern, not folder installs.
- **Files' index.** Pointed at an empty scratch folder (`PANE_TEST_FILE_INDEX_HOME`, development builds only), so the phase measures idling, not a first walk of the home folder.
- **The "one show".** A single start, hidden right away (before setup finishes), then the five defaults recorded, a 30 s settle (`PANE_MEASURE_SETTLE_SECONDS` / `-SettleSeconds`), then 60 s hidden. There is no second start, so Windows shows Pane only once. Leftover start work (icon extraction) counts in the phase and is attributed by thread.
- **What a wake-up is.**
  - Linux: voluntary context switches. Involuntary ones are kept in the samples but not summarized.
  - Windows: `ContextSwitches` (all switches). `wakeups.counted` says which.
  - Samples carry `tick_hz` and `switch_kind`, so one `summary` reads both platforms.
- **Windows targets.** None yet, so the Windows script runs `summary`, not `check`.
- **Scratch location.** The Windows scratch profile is a new folder in `%TEMP%`. It is removed at the end because it holds whatever Clipboard History recorded (`-KeepScratch` keeps it). Outputs go to `-OutDir`.
