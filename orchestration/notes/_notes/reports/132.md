## Design notes and ambiguities I resolved

- **Footer message.** AccessKit (consumer 0.37/0.38) treats a node as live only when it has an explicit `live` value. The footer strip's `Role::Status` is therefore not announced today. Making the strip itself live would make all its children live too (buttons, the Actions panel), because they inherit the value. So the strip keeps its `Status` role and name, and the announcer also speaks the footer's message: the toast, or the status line, including "Running…".
- **Message and selection together.** The message is said first, and the selection's text is held for 500 ms (`STATUS_LEAD`). I chose this value myself: Narrator and NVDA read the name when they handle the UIA event, so the text must not be replaced too early.
- **Wording I chose:**
  - opening: "<name>, <n> results. <row>"; "1 result" and "1 command" in the singular; "<name>, 0 results" for an empty list;
  - the Actions panel's name is its dialog label, "Actions for <target>" (or "<submenu>, actions for <target>");
  - the footer menu says only its selected item, "Settings, 1 of 1";
  - root search says nothing when it opens, or when you come back to it;
  - forms and custom views say nothing.
- **Section prefix.** It is added only on user moves, not on typing or on changes Pane makes.
- **Announcer role.** It uses `Role::Label` (UIA Text, macOS static text), not `Status`, so that NVDA's "read status bar" command still finds the footer.
- **New field nodes.** The Actions panel's filter and Clipboard History's search now have `EditableComboBox` nodes, like root search and Search Files, so the focus check has a node to land on.
- **Repeated text.** The same text said twice in a row is not re-announced, because the tree does not change. For example, reopening the footer menu says "Settings, 1 of 1" again and nothing is heard. This is documented as a limit.
- **Settling depends on every search finishing.** "Settled" waits until every query-field search future has resolved, including the first query's indexed results. A provider that never answers would hold typing announcements until the runtime gives up on it.

## Look here first when compiling

- **Formatting.** It is done by hand against rustfmt's width heuristics (`fn_call_width` 60, `chain_width` 60, `single_line_if_else` 50). Run `cargo fmt` first.
- **Borrows.** Disjoint-field borrows such as `self.announcer.user_moved()` while `self.menu`, `self.actions` or `self.clipboard` is mutably borrowed. Also the `follow()` layer selection in `announcer.rs`.
- **Zero-size absolute node.** Is a zero-size `.absolute()` `div` with an id and a role still pushed into GPUI's a11y tree? I expect so (no clip filter in AccessKit), but did not confirm it in GPUI's paint path.
