## Unsure, not confirmable by reading (check here first)
- **Icon embedding.** The repo embeds no program icon resource: there is no build.rs or .rc, and the old adapter's `LoadImageW(id 1)` always fell back to `IDI_APPLICATION`. The `.ico` files are therefore embedded with `include_bytes!`. The adapter picks the image itself (`icon_image`) and calls `CreateIconFromResourceEx(image, TRUE, 0x00030000, size, size, LR_DEFAULTCOLOR)` on a 32-bpp BMP entry. These are not `RT_GROUP_ICON` resources; that would need embed-resource and a Cargo.lock edit.
- **Notification version 4.** The adapter now sets version 4. Clicks map as `NIN_SELECT`/`NIN_KEYSELECT` → summon and `WM_CONTEXTMENU` → menu at the `wParam` anchor, and the raw mouse messages are ignored. If `NIM_SETVERSION` is refused, the old mapping (`WM_LBUTTONUP`/`WM_RBUTTONUP`) is used. `NIF_SHOWTIP` is added for the tooltip. Confirm natively that a left click summons exactly once and the menu opens once.
- **Retry after a refused add.** A refused `NIM_ADD` is retried once after an `NIM_DELETE` of the same identity. This covers a stale icon a crash left behind under the same GUID, and "already exists" after a `TaskbarCreated` that did not actually drop the icon (assumed behaviour).
- **Icon handles.** Old `HICON`s are destroyed right after the next `Shell_NotifyIcon` call. This assumes the shell copies the icon.
- **DPI.** DPI comes from `GetDpiForWindow` on the hidden top-level window (system or primary DPI). On `WM_DISPLAYCHANGE`/`WM_DPICHANGED` the icon is redrawn. Whether the hidden window receives those is unconfirmed.
- **Linear scaling.** The size test assumes `GetSystemMetricsForDpi(SM_CXSMICON, dpi) == 16*dpi/96`.
- **Elevated Pane.** `ChangeWindowMessageFilterEx(TaskbarCreated, MSGFLT_ALLOW)` is called for an elevated Pane; its result is ignored.
- **macOS API calls.** Not compiled anywhere yet: `NSImage::initWithData(NSImage::alloc(), &data)` (`objc2::AnyThread`), `setSize(NSSize::new(18.0, 18.0))`, `setTemplate`, `setAccessibilityDescription`, `button.as_super().setImage(Some(&image))`, and `item.setAutosaveName(Some(&NSString))` (set before `setVisible(true)`). `NSSize` is exported because app-kit's `NSImage` feature turns on `objc2-foundation/objc2-core-foundation`.
- **Formatting.** I formatted by hand. Import lists were checked against a width model calibrated on all 357 repo files. Let-chains, match arms and the `self.shell.report(&format!(\n…\n))` overflow form are my best reading of rustfmt, so `cargo fmt --check` may still want small changes.

## Spec ambiguities resolved
- **What "the preference is to show it" means inside the adapter.** It is the visibility Pane last asked for (`wanted`), kept even when the system refused the request. A show refused at sign-in, before Explorer is up, is then added at the first `TaskbarCreated`. The cost: a show refused from the General page switch, where the record stays off, would also be added at the next Explorer restart.
- **GUID name.** The GUID is derived from the `std::fs::canonicalize(current_exe())` path, including the `\\?\` prefix, hashed as UTF-16LE code units. The namespace is `da8fe9f2-34cb-4924-bc6c-180e89a5ae57`. Once the system refuses the GUID, the numeric id is used for the rest of the run. A refusal of both the GUID and the numeric id keeps the GUID for the next try.
- **High contrast (proposed).** The variant is chosen by the luminance of `GetSysColor(COLOR_WINDOW)` under `HCF_HIGHCONTRASTON` (threshold 0.179), so the mark stands out from the background. The icon is not redrawn in system colours.
- **Icon art.** The two squares share one colour, so the back square's stroke stops 1.25 units short of the front square to keep them apart. Sizes are 16, 20, 24, 28, 32, 36, 40, 48, 56 and 64. The macOS template is 36 px drawn at 18 pt. Colours are pure black and white.
- **Diagnostics.** They go to standard error through the adapter's existing `log`. The crash-log ticket can route them later.
