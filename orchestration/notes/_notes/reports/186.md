## What was built

- **`Scope`** (`scope.rs`):
  - `kept: Mutex<Admitted>`, used through `admits_kept`. It is capped at 20,000 folders and dropped whole past that.
  - `forget_kept(folder)` drops the folder and every folder under it. `Admitted` gained a `below` map (parent → known children), so this does not scan the whole cache. It works because a folder is cached only once its parent is.
  - `forget_all_kept`.
  - `global_ignore_changed()` compares the size and mtime of git's config files and of the excludes file. Both are stamped before the global matcher is read.
  - `same_global_ignore(&other)`.
  - A new `Scope` keeps nothing. That covers a change of the user's rules (the coordinator restarts), a quarantine and a global-ignore change.
- **Coordinator** (`indexer.rs`):
  - `forget_changed` runs on every batch, before churn and `look_at`. It forgets each reported path. For `X/.gitignore`, `X/.ignore`, `X/CACHEDIR.TAG`, `X/.git/info[/exclude]` and `X/.git` it forgets `X` and re-checks it.
  - A `.git` counts only when it appears or goes (`repositories` map). The first time a `.git` is named, one made more than 2 s before the run started counts as already there; this is not used during macOS's history replay. This stops Windows' reports of Git's work inside `.git` from re-walking repositories.
  - An overflow (`Rescan`) forgets everything.
  - A global-ignore change builds a new `Scope`. It re-checks every kept root if the excludes file itself changed.
  - `recheck_folders`:
    - If the folder is no longer admitted, `RemoveUnder`.
    - Otherwise `walk_folders` walks it under the current rules and diffs the result against the index (`children`, recursively).
    - Removals cover what is gone, left out or of another kind. Puts cover what is new or changed.
    - What a hung folder holds is kept, and nothing is removed if the ceiling was reached. A stop throws everything away.
  - Catch-up changes naming those files queue the folder in `recheck`. It is deferred like the other walks and runs in `do_walks`.
  - Everything kept is dropped once watching starts, because a change between the catch-up and the watch is reported by neither.
  - `count_churn`, `admits_change`, `look_at` and `catch_up_changes` use `admits_kept`.
- **`Indexer::checked`** uses `admits_kept`. If the global ignore file changed since the scope was built, it uses a freshly built `Scope` instead.

## Ambiguities resolved

- **"Prefer dropping too much".**
  - A reported folder drops its whole subtree, which covers hidden-attribute changes, renames and deletes.
  - An overflow drops everything.
  - Watching's start drops what the catch-up learned.
  - `.gitignore`/`.ignore` and their siblings are matched in any letter case.
- **Re-check scope.** The folder is walked whole and compared, rather than only its direct entries, because patterns apply deeper. An ignore file changed in the home folder, or a change of the global ignore file, therefore walks every root (at background priority). This is in the Limits section.
- **Global ignore.** It is looked at once per batch (about 5 stats), so on its own it is noticed with the next change under a root. Linux does not watch `~/.config`. This is documented.
- **Check at Enter.** It shares the cache, as the ticket asks. For about the settle time after an ignore file changes it can still judge by the old rules. This is documented as a limit.
- **Remaining limits, documented and not fixed.**
  - Linux's reconciling catch-up re-reads only folders whose time changed.
  - Linux does not watch inside `.git`, so a change to `.git/info/exclude` alone is not seen there.
