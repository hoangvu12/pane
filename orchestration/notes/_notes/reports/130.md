## Design
- New `crates/pane-core/src/protection.rs`:
  - `Stored` records how a value is written: `{"plain": …}` or `{"dpapi": base64}`.
  - DPAPI uses `CryptProtectData`/`CryptUnprotectData` in user scope, with a fixed `ENTROPY` and `CRYPTPROTECT_UI_FORBIDDEN`.
  - `Value` holds a value in memory: its stored form, plus its decrypted text, filled lazily and cached.
- `credentials.json` on Windows is version 2: `FileJson<Stored>`. It is written as version 1 when the kind is not protected here and every value is plain, so macOS and Linux are unchanged. Other kinds stay at version 1. Credentials read versions 1 and 2. Every other version is refused, with the message "this Pane reads 1 and 2".
- Conversion runs in `KindFile::open` (ExtensionData::open, at launcher start) as one direct `write_atomically`. If it fails, memory keeps the values and the file stays version 1. It is retried at the next start.
- `set` protects the value before taking the lock. `change_preferences` reuses the stored bytes of unchanged values. A password preference that cannot be read is treated as unset and kept until it is set again.
- Clipboard history:
  - Each `Item` gets `pub unreadable: Option<String>` and a private `Sealed`, an `Arc<OnceLock<Stored>>` shared by clones. The item is encrypted once, at its first write, and later writes reuse the bytes. #192 can batch on top of this.
  - The file keeps `id`, `copiedAt`, `source` and `image` readable. `text` and `files` go into `protected`.
  - It is version 2 on Windows and converted in `HistoryStore::open`.
  - An unreadable item's text is its explanation. `Commands::copy` and `paste_clipboard_record` refuse it, and `ClipboardRecord` gains an `unreadable` field.
  - `counts_now` reads without decrypting.
- `#[doc(hidden)] pane_core::clipboard::revealed_history(text)`: tests use it to read the history file's texts.

## Spec ambiguities resolved
- **Version rule:** a file is version 2 where the system protects it, or where a value or item is protected (for example a Windows folder read on Linux, whose values are kept as they were). Otherwise it is version 1, so macOS and Linux are unchanged. On Windows an empty credentials or history file is version 2 too.
- **"Without decrypting anything":** read, count, clear, uninstall and delete never decrypt. Only the "N unreadable" note on Manage extensions tries the protected values, keeping just the count of failures.
- **What is encrypted in an item:** only its text and files. Id, time, source program and image metadata stay readable, so expiry, deletion, counting and PNG pruning work without decryption.
- **Image PNGs** in `clipboard-images/` are not encrypted (user-only as before). The UI loads them by path. This is documented.
- **An unreadable clipboard item** is shown with its explanation as its text. It cannot be copied or pasted, only deleted or left to expire.
- **Unreadable credentials in Manage extensions** only appear for retained data: installed packages' credential counts are not shown there today. The test uses a retained identity.
