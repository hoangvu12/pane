## What changed

- **New `file_index/volume.rs`.** It holds `VolumeKind` (Local/Network/Removable), `VolumeKinds` and `volume_kind`. When the system gives no answer (a missing root, a failed call) the kind is Local, so a root that is away keeps its entries.
  - Windows: `files::is_network_path` decides a share by its text first. Otherwise `GetVolumePathNameW` resolves the path to its volume root, falling back to the drive letter's root when that fails, and `GetDriveTypeW` reads that root.
  - macOS: `statfs` `f_flags`.
  - Linux: the old walker statfs list, now split into network and removable.
- **`Scope`.** New methods: `with_volumes`, `volume_kind`, `root_volume` (asked once per scope through a `OnceLock`), `leaves_out_root`, `kept_roots`, `watched_roots`, `network_roots`, and `leaves_out_mount` (crate-only).
  - `admits` and `context_at` admit nothing under a root that is left out.
- **Walker.** `walk` skips a left-out root without touching it and counts it in `excluded`.
  - `walk_folders` asks `admits` before `meta_at`, and skips a new folder that is another volume the rules leave out.
  - `list_job` uses `leaves_out_mount`, which replaces the Linux-only `other_volume`.
- **Reconcile.** A left-out root removes whatever is indexed under it without being looked at. `read_again` applies `leaves_out_mount`.
- **Change sources.**
  - NTFS and FSEvents catch up from, and take cursors from, `kept_roots`. They and inotify watch only `watched_roots`.
  - Linux catches up over `kept_roots`.
- **Coordinator.**
  - When the index opens it removes entries under roots that are now left out.
  - It keeps `network` (the shares kept by the switch). At catch-up it adds them to `reconcile`, and it reconciles them again every `reconcile_unwatched` alongside Linux's unwatched folders.
  - It filters folders on a share out of `indexed_folders()` and `add_watches`.
  - `walk_added_roots`, `Caught::Reconcile`, low-space recovery and `roots_away` now use `kept_roots`.
- **Churn.** `handle` collects every reported path, keeping repeats.
  - One `Admitted` memo per batch is passed to `count_churn` and then to `look_at`. It is reset to a fresh memo after a quarantine, because the rules changed.
  - `count_churn` counts a path only if `admits_change` returns true. That function gets `is_dir` from `symlink_metadata`, or from the index once the path is gone, and asks `Scope::admits` once per distinct path. The old excluded-folder check is subsumed.

## Unsure, look here first when compiling

- **`MNT_REMOVABLE = 0x200`** is defined locally in `volume.rs`, because the `libc` crate (0.2.189) does not have it. I took the value from memory of XNU's `<sys/mount.h>`, so check it against the SDK. `MNT_LOCAL = 0x1000` is confirmed in libc.
- **Windows APIs.** `GetDriveTypeW(PCWSTR) -> u32` and `GetVolumePathNameW(PCWSTR, &mut [u16]) -> Result<()>` are confirmed in windows 0.62.2 under `Win32_Storage_FileSystem`, which is already enabled; no feature was added. The drive-type values 2, 4 and 5 are written as numbers and match the `WindowsProgramming` constants.
  - Not confirmed: that `GetVolumePathNameW` returns the drive letter for a mapped drive, and that `GetDriveTypeW` says remote for it. A `subst` drive is reported as whatever the underlying drive is.
- **rustfmt.** Formatting was done by hand against the default widths (`fn_call_width`/`chain_width` 60). The most likely places for `cargo fmt` to differ are the `assert!`/`assert_eq!` layouts in the new tests and `Scope::root_volume`'s `map_or` closure.
- **Let-chain** in `walk_folders` (`if … && let Ok(above) = meta_at(parent) && …`). The crate already uses let-chains.
- **Test timing.** The share test relies on the periodic reconcile with `reconcile_unwatched = 50ms`. The churn test runs about 4–5 s.

## Spec ambiguities and how I resolved them

- **Added roots on other volumes are left out by default.** I followed the ticket and docs/files.md (`includeOtherVolumes`), which leave them out. This is in tension with spec stories 51/52, which read as "left out unless I add them" and have an added USB drive indexed. The existing `an_added_root_away_…` test still passes, because its temp folder is local.
- **The root check applies on Linux too.** I did this for the one-behaviour rule, Q8. Linux previously checked only mounts below a root. As a result, a Linux home on NFS or FUSE, or an added FAT/exFAT root, is now left out by default. This is documented under Limits.
- **"Never watched, only reconciled" is done for roots only.** A share mounted below a root on macOS or Linux, once included, is still watched with its root. Doing better needs FSEvents exclusion paths or volume-aware inotify filtering. This is documented under Limits.
- **Reconcile interval for an included share.** The spec gives none, so it uses `RECONCILE_UNWATCHED` (5 min), the same as Linux's unwatched folders. Shares are not counted in `status.unwatched`, since that problem text is about inotify.
- **No new "needs attention" problem for a left-out root.** Adding one would mean UI changes. The File Search page still lists the root among the indexed folders; this is documented as a limit.
- **Noted, not changed.** With the switch on, an entry under a UNC root is found but refused at Enter ("it is on a network location", from `Indexer::checked` step 1). A mapped drive letter is opened. This is documented as a limit.
- **Memo use for #186.** I kept it simple: one `Admitted` per batch, shared by `count_churn` and `look_at`, and replaced after a quarantine.
