#129 Quick fixes: protected credentials, a tray icon that survives Explorer, screen-reader announcements, a correct hotkeys document, and a local crash record
## Problem Statement

Five small gaps make Pane less trustworthy than it should be. None needs a new design, and each is known from the code or from the Raycast research ([research](https://github.com/hoangvu12/pane/blob/main/docs/research/raycast-deep-dive.md#shell-and-platform)).

- **Credentials are plain text.** An extension's local credentials, such as sign-in tokens, are kept in `credentials.json` in Pane's data folder as plain JSON. On macOS and Linux the file is readable by the user only (mode 0600), and on Windows it carries a DACL for the user and SYSTEM. Anything that copies the file can read every token: a backup, a synced or roamed profile, a disk read outside Windows, or an administrator's tool. Raycast protects its secrets with DPAPI on Windows.
- **The tray icon disappears when Explorer restarts.** Pane's Windows tray icon is added once at start. When Explorer restarts (after a crash, an update, or a user restarting it), the notification area forgets every icon. Programs must add theirs again when Windows broadcasts `TaskbarCreated`, and Pane ignores that message, so its icon stays gone until Pane restarts. The icon has no stable identity either, so Windows cannot keep the user's "always show" choice for it. It is also one embedded icon that ignores whether the taskbar is light or dark. On macOS the menu bar item shows the word "Pane" instead of an icon.
- **Screen readers cannot follow the selection.** Root search keeps the caret in its query field and reports the selected result as the field's active descendant. GPUI CE implements this by reporting the result itself as focused, so a screen reader may read results instead of echoing what the user types. No screen reader has been run, and root search's screen-reader goal (G2) cannot pass this way ([root search](https://github.com/hoangvu12/pane/blob/main/docs/root-search.md#accessibility)).
- **The hotkeys document is wrong.** The [global hotkeys](https://github.com/hoangvu12/pane/blob/main/docs/hotkeys.md) document says Pane has "no hotkey of Pane's own to summon its window". The decision index says the same. Since [#74](https://github.com/hoangvu12/pane/issues/74), Pane has the Open Pane hotkey on the General page. Since [#76](https://github.com/hoangvu12/pane/issues/76), command hotkeys can also be recorded in Settings' Shortcuts page. The document says neither.
- **A crash leaves no trace.** Pane writes its diagnostics to standard error. On Windows a release build is a windowed program, so standard error goes nowhere. Runtime crash details, pause reasons and failures to save are all lost there, and on every system a crash that ends the process leaves nothing behind. The user learns nothing at the next start, and a bug report has nothing to attach.

## Solution

Five independent fixes, each its own ticket.

1. **Protected credentials.** On Windows each credential value is encrypted with DPAPI for the current user, with Pane-specific entropy, and the clipboard history file gets the same protection. Values already stored are converted on the first start. A value that can no longer be decrypted is explained, never dropped or replaced silently. macOS and Linux keep today's user-only file in this slice. Later, flagged slices in this specification protect them with the macOS Keychain and the Secret Service, once their prerequisites hold.
2. **A tray icon that survives Explorer.** On Windows Pane adds its icon again when Explorer restarts. The icon gets a stable identity, so the user's notification-area choice is kept across restarts and application updates. Its light or dark variant follows the taskbar's theme. On macOS the menu bar item becomes a template image of Pane's mark, which the system tints for light and dark menu bars. Linux still has no tray entry.
3. **Announcements of the selected row.** Keyboard focus stays in the query field, and result rows stop claiming focus. One hidden live region announces "<title>, <i> of <n>" when the user moves the selection. It also announces a page's name and count when one opens, and "No results" when a list is empty. This follows the pattern PowerToys Command Palette uses with Narrator and NVDA. AccessKit carries the live region to Narrator and NVDA on Windows, VoiceOver on macOS and Orca on Linux.
4. **A correct hotkeys document.** The hotkeys document and the decision index describe the Open Pane hotkey and Settings' Shortcuts page as they are.
5. **A local crash record.** Everything Pane writes to standard error also goes to a log file. The log is size-capped, rate-limited and redacted: the home folder, the user's name and the computer's name are removed. A panic is written there before the process ends. A marker written at start and removed at a clean quit lets the next start say "Pane quit unexpectedly last time" and point at the log. Nothing is sent anywhere.

## User Stories

### Protected credentials

1. As a user who signs in to services through extensions, I want my tokens encrypted on disk, so that a copy of Pane's data folder does not hand them to whoever holds it.
2. As a Windows user, I want my credentials readable only by my Windows account, so that another account or an offline read of the disk cannot use them.
3. As a Windows user, I want credentials I saved before this change protected automatically on the next start, so that I do not have to sign in again.
4. As a user, I want the protection to need no password prompt and no extra service, so that extensions keep working exactly as before.
5. As a user whose Windows password was reset by an administrator, or who copied Pane's data to another computer, I want a credential that can no longer be decrypted to be explained and offered for signing in again, so that I understand why I am signed out.
6. As a user, I want a credential that cannot be decrypted never to be deleted or replaced without my action, so that a temporary failure does not lose my sign-in.
7. As a user, I want Clear cache, uninstall and deleting retained data to work on protected credentials, without decrypting them, as they do today, so that managing an extension does not depend on decryption.
8. As a user, I want Manage extensions and the uninstall confirmation to keep counting my credentials, so that I know what will be removed.
9. As a macOS or Linux user, I want Pane to say exactly how my credentials are protected on my system, so that I do not assume protection I do not have.
10. As a macOS user, I want my credentials kept behind the Keychain once Pane is signed, so that I get the protection my system offers without a Keychain prompt after every update.
11. As a Linux user with a keyring (GNOME Keyring, KWallet, KeePassXC), I want Pane to keep its credential key there once that slice lands, so that my credentials are encrypted when the keyring is available.
12. As a Linux user without a keyring, I want Pane to keep working with the user-only file and to say so, so that a missing keyring does not break extensions.
13. As an extension author, I want `credentials.get` and `credentials.set` unchanged, so that my extension needs no rebuild for the protection.
14. As an extension author, I want a credential Pane cannot decrypt to reach me as an error I can turn into "sign in again", so that my extension can recover on its own.
15. As a user who goes back to an older Pane, I want it to say it cannot read the newer credentials file, not overwrite it, so that a downgrade does not destroy my tokens.
### The tray icon

16. As a Windows user, I want Pane's tray icon to come back by itself after Explorer restarts, so that I can still reach Pane from the notification area.
17. As a Windows user, I want the icon to come back only if I chose to show it, so that a hidden icon stays hidden.

24. As a Linux user, I want the General page to keep saying that Pane has no tray entry on Linux, so that I am not misled.
25. As a user, I want the tray menu to stay Open Pane, Settings and Quit, so that the fixes change nothing else about it.

## Implementation Decisions

### Scope and decision provenance

- **Decided by the user (2026-10-06):** these five items as one specification. Credentials are encrypted at rest with DPAPI on Windows. The tray icon is added again after Explorer restarts, with a stable id and a theme-aware icon. Narrator announces the selected row as "title, i of n" through a live region while focus stays in the query field. The stale statement in the hotkeys document is fixed. Pane gets a local crash marker and a redacted, size-capped log.
- **Proposed defaults the user delegated ("like Raycast, as flexible as possible"):** credentials use Windows DPAPI now, with the macOS Keychain and Linux Secret Service as later, flagged slices that do not block this specification; `clipboard-history.json` gets the same protection on Windows; the crash notice is a one-time row in root search at the next start plus the About page; announcements use a polite live region.
- **Proposed defaults here (not separately confirmed):** the details of the macOS and Linux slices, the stable-identity derivation, the announcement wording beyond "title, i of n" and its timing, the log's location, sizes, rate limit and redaction set.
- Each item is its own ticket with no dependency on the others. The fixes stay within the accepted UI ([ADR 0029](https://github.com/hoangvu12/pane/blob/main/docs/adr/0029-the-ui-is-accepted-as-built.md)): only the crash notice and the explanation of a credential that cannot be decrypted add visible text.

### 1. Protected credentials

- **The seam:** extension data gains a credential protector, one per system, between the values in memory and the `credentials.json` file. Values stay plain in memory while Pane runs, and only the file changes. The `credentials` interface in `wit/data.wit` does not change, so no component is rebuilt. Its doc comment and the [extension data](https://github.com/hoangvu12/pane/blob/main/docs/extension-data.md) document change to describe the protection.
- **Windows:** each value is protected with DPAPI (`CryptProtectData`) in the current user's scope, with a fixed Pane-specific entropy and the flag that forbids any prompt. Only values are protected. The identity and key names stay readable, so Clear cache, uninstall, deleting retained data and the counts on confirmations work without decrypting anything, as they do today. The file keeps its protected DACL.
- **The file format:** the credentials file moves to format version 2, in which each value records how it is protected. The other kinds' files stay at version 1. On Windows, Pane converts a version-1 file to version 2 at start, protecting every value, in one atomic write. If that write fails, Pane keeps reading the version-1 file and tries again at the next start; no value is lost either way. An older Pane refuses a version-2 file, as every Pane refuses a file of another version, and never overwrites it.
- **A value that cannot be decrypted:** this happens when the user's DPAPI master key was lost to an administrator's password reset, when the data folder was copied from another user or computer, or when the file was damaged. Then `credentials.get` returns an error the extension can act on: "Pane cannot read this credential on this computer: Windows could not decrypt it (<reason>). Sign in again." `set` replaces the value, and Pane never drops or regenerates it on its own. Raycast's rule ("key lost but data exists: explain, never regenerate") is taken. Manage extensions shows an extension whose credentials cannot be read as "keeps 2 credentials, 1 unreadable".
- **What it protects against, said plainly:** another user of the computer, a copy of the file (a backup, a synced profile, a disk read outside Windows) and an administrator reading the file without the user's sign-in. It does not protect against programs running as the same user. They can call DPAPI too, and Pane's entropy is in its program. So the [data policy](https://github.com/hoangvu12/pane/blob/main/docs/extension-policy-proposal.md#disable-cache-data-and-uninstall)'s "lifecycle behavior, not secret isolation from trusted code" stands. The documents keep saying so, and the decision index's "Local credentials are plain text" statement is updated.
- **macOS, this slice:** unchanged. The file stays plain JSON with mode 0600, and the documents say that this is how it is protected on macOS.
- **macOS, a later flagged slice:** Pane keeps one random data key in the login Keychain as a generic password item and encrypts each value with an authenticated cipher under that key. The rest works as on Windows (version 2, readable keys, explain-never-regenerate). It waits for Pane to be signed. The Keychain ties an item's access to the program's code signature, and an unsigned Pane replaced in place by an application update would make macOS ask the user for Keychain access after every update.
- **Linux, this slice:** unchanged. The file stays plain JSON with mode 0600.
- **Linux, a later flagged slice:** where a Secret Service provider is running and unlocked (GNOME Keyring, KWallet, KeePassXC, through the freedesktop Secret Service interface on the session bus), Pane keeps its data key there and encrypts values as on macOS. Where none is available (no session bus, no keyring, a headless session), it keeps the user-only file. Manage extensions then says the credentials are not encrypted, and why. A keyring that later disappears is treated like a key that cannot decrypt: explained, never regenerated.
- **Clipboard history on Windows (proposed default, delegated):** `clipboard-history.json`, written with the same user-only protection as credentials and able to hold copied secrets a password manager did not mark, is protected with the same DPAPI protector: each kept item's content is encrypted. It moves to a new format version, is converted at start in one atomic write as credentials are, and an item that cannot be decrypted is explained and left in place, never silently dropped. On macOS and Linux it follows the credentials' later slices.
- **Out of this item:** the Windows Credential Manager, which Raycast uses mainly to survive DPAPI corruption.

### 2. The tray icon

- **Windows, coming back after Explorer restarts:** the tray adapter's window registers the `TaskbarCreated` message. When Windows broadcasts it, the adapter adds the icon again with its identity, icon, tooltip and callback, and sets the notification version again. It does this only while the user's preference is to show the icon. A hidden icon stays hidden, and the preference record does not change. A re-add the system refuses is reported in the log and tried again at the next broadcast; the General page's switch still reflects the preference.
- **Windows, stable identity:** the icon is added with a GUID (`NIF_GUID`). The GUID is derived as a name-based UUID from a fixed Pane namespace and the program's canonical path, so it stays the same across restarts and across application updates, which replace the program at the same path. Windows ties a notification icon's GUID to one program path unless the program is signed, so a development build at another path gets a GUID of its own. If the system refuses the GUID, the adapter falls back to today's numeric id and logs why.
- **Windows, theme-aware icon:** the adapter reads the taskbar's theme from the user's personalization setting `SystemUsesLightTheme`. This is not the setting for applications' theme, and not Pane's own Appearance choice, because the taskbar can be dark while applications are light. It shows the matching variant of Pane's mark. When the system broadcasts a theme change (a settings change for `ImmersiveColorSet`), it changes the icon in place. Each variant is loaded at the notification area's small-icon size for the display's DPI. High contrast uses the system's own colours where the variant would not meet contrast (proposed).
- **Icon art:** two monochrome variants of Pane's existing mark, one light and one dark, embedded as multi-size icon resources in the program. On macOS the mark is a template image. This is Pane's own art, not Raycast's.
- **macOS:** the status item's button shows the mark as a template image (`isTemplate`) instead of the title "Pane". macOS tints a template image for light and dark menu bars and for the selected state. The item has an autosave name, so a position the user Command-dragged it to is remembered. The item belongs to Pane's process, so a restart of the system's menu bar processes needs no action from Pane. This is to be confirmed by the native run.
- **Linux:** unchanged. There is no entry (StatusNotifierItem over DBus is separate work), and the General page's explanation stays. When that work is done, it must register again when the StatusNotifierWatcher reappears, the Linux counterpart of `TaskbarCreated`.
- **Unchanged:** the menu (Open Pane, Settings, Quit or Exit, in the platform's own labels), left click summoning the launcher, and the preference and its rollback.

### 3. Screen-reader announcements

- **Focus:** in root search, AccessKit focus stays on the query field (the editable combo box). The selected row no longer reports itself as focused: the active-descendant claim is removed from root search's rows and computed answers. Each row keeps its list-box-option role, its label, description and selected state. It gains its position in the set and the set's size, so a screen reader that inspects the list hears where a row is. Command lists, the actions panel, the footer menu and the clipboard history view get the same change wherever focus stays in a field or menu while a row is selected. A list with no field keeps focus on the list.
- **The announcer:** each launcher window has one hidden, zero-size node of Pane's own that is a live region. GPUI CE already offers `aria_live`, `aria_live_atomic`, `aria_label` and `aria_value`. The announcement text is set as both the node's name and its value. AccessKit's Windows and Linux adapters announce a live region's name; its macOS adapter announces the value. With both set, Narrator and NVDA (UI Automation's live region event), Orca (AT-SPI's announcement) and VoiceOver (an announcement request) all get the same text.
- **What is announced** (proposed wording, in the launcher's language, which is English today):
  - On a selection move by the user (arrows, Alt+Up/Down, Ctrl+Up/Down and the Alt-based Emacs and Vim keys of the "Launcher polish" specification (#123), Home/End, number chords, the pointer): "<title>, <i> of <n>". The user decided this form. Two additions are proposed: ", unavailable" for an unavailable row, and the section's name before the title when the move enters another section ("Fallbacks: Search the web, 1 of 2").
  - On opening a command, a page or the actions panel: "<name>, <n> results" (or "<n> commands" in the actions panel), then the selected row as above.
  - When a list becomes empty: "No results".
  - After the query changes: nothing for each keystroke. Once the results stop changing (proposed: when the current query's results have settled, or 300 ms after the last keystroke, whichever comes later), the selected row is announced only if it is not the one last announced. This keeps typing echo and avoids the cascade PowerToys Command Palette had to fix.
  - When the selection is changed by Pane rather than the user (a late result arriving, a list refreshed), nothing is announced unless the selected row's identity changed.
- **Urgency:** polite for everything, so the screen reader's own typing echo is not cut off (proposed default, delegated). Each new text replaces the last, so fast arrowing collapses to where the user stopped. The footer's status strip stays a status live region. When both change at once, the selection's announcement waits for the status (proposed order: the status first).
- **Unchanged:** the custom view's and the forms' accessibility, which have their own records; Settings' controls.
- This removes root search's dependence on GPUI CE's active-descendant support. The open item in root-search.md and the decision index is updated: G2's remaining condition is a native run with each screen reader, not a GPUI change.

### 4. The hotkeys document

- The [global hotkeys](https://github.com/hoangvu12/pane/blob/main/docs/hotkeys.md) document's Limits section stops saying there is no summon hotkey. A short section describes the Open Pane hotkey ([#74](https://github.com/hoangvu12/pane/issues/74)):
  - It is the application's own global hotkey, set on Settings' General page. It summons the launcher when hidden, focuses it when unfocused and hides it when focused.
  - Its defaults are Ctrl+Alt+Space on Windows and Linux and Option+Space on macOS, and it can be recorded and reset there. (Once the "Windows power features" specification (#125)'s keyboard hook lands, a fresh install on Windows defaults to the Windows key alone, ADR 0039; the document changes again with that slice. This item describes what ships now.)
  - It is kept in Pane's own settings record and is independent of any extension.
  - The same registration adapters and limits apply, including Wayland's.
- "Assigning one" says that command hotkeys are recorded in Manage extensions or inline in Settings' Shortcuts page ([#76](https://github.com/hoangvu12/pane/issues/76)), as one record with the same rules. The refusal table gains the collision with the Open Pane hotkey.
- The same statement in the decision index's root search item ("there is no summon hotkey of Pane's own") is corrected, with a link to #74.
- Documentation only. No code changes, and no ADR is needed for this item: ADR 0016 describes what ships today accurately. ADR 0039 amends it for the keyboard hook and the Windows-key default, which the "Windows power features" specification (#125) implements and documents.

### 5. The local crash record

- **One diagnostic path:** every message Pane writes to standard error (about 25 places in the two crates today) goes through one diagnostic function. It writes to standard error as now, and to the log. Guest output is not included; making extension logs visible is the "Making extensions easier to build" specification (#128)'s.
- **Where:** a logs folder in the platform's place for logs: `%LOCALAPPDATA%\Pane\logs` on Windows, `~/Library/Logs/Pane` on macOS (where Console shows it) and `$XDG_STATE_HOME/pane/logs` (by default `~/.local/state/pane/logs`) on Linux. When `PANE_DATA_DIR` is set (tests and smokes), the folder is `logs` inside it. The folder is readable by the user only.
- **Size and rotation (proposed):** one file, `pane.log`, appended to across starts. When it passes 2 MiB it becomes `pane.1.log`, the older ones shift, and at most 5 old files are kept, so the log never exceeds about 12 MiB. Each line has a UTC time, Pane's version at the start of each run, and the message.
- **Rate limit:** at most 10 lines a minute from one site (the message's fixed text, before its values). When more arrive, one line says how many similar lines were left out. A loop of errors cannot fill the disk.
- **Redaction, at the log's writer, before anything is written:**
  - The home folder's path becomes `~`.
  - The user's name becomes `<user>`, and the computer's name becomes `<computer>`. Both are matched without regard to case, and only when at least 3 characters long.
  - Other paths are kept, since they are needed to diagnose.
  - The log carries only what Pane's own diagnostics say. They are reviewed so that none includes extension data values, credentials, clipboard text, query text or found file names. A test fixes this for the messages that name user data.
- **Panics:** a panic hook writes the panic's message and location (and its backtrace when one is captured) to the log before the default handling. A panic of the extension runtime's thread is already recovered without ending Pane (#17), and is logged like any other message.
- **The marker:** at start Pane writes a marker in the logs folder with its process id, its start time and its version. A clean quit removes the marker. Clean quits are the Pane menu's or tray's Quit, closing the launcher by the quit path, and the system ending the session: `WM_ENDSESSION` on Windows, the application's termination notification on macOS, and SIGTERM, SIGINT or SIGHUP on Linux. At the next start, Pane checks each marker it finds:
  - A marker whose process is no longer running (the same id and start time) means that run ended unexpectedly.
  - A marker whose process still runs belongs to another Pane on the same folder and is left alone.
  - Each start writes its own marker.
- **The notice (proposed default, delegated):** after an unexpected end, root search shows one row, "Pane quit unexpectedly last time", whose action opens the logs folder with the system's file manager. It works like the application update row (#54): a row in root search plus the status line, using no new UI element. Settings' About page shows the same notice next to its diagnostics, with "Open log folder" and "Copy diagnostics", where diagnostics now include the log's location. The notice goes when the user dismisses it, opens the folder, or Pane next quits cleanly and starts again.
- **Nothing is sent.** There is no telemetry and no crash upload, in keeping with the About page's "nothing invented, nothing uploaded". Minidumps are not written.

## Testing Decisions

- A good test checks what the user, the screen reader or an extension observes: a value read back, an icon present, an announcement's text, a notice shown. It never checks a private structure.
- **Credentials:**
  - Seam: the `Launcher` public interface, with each language's settings sample, which keeps a token, in `crates/pane-core/tests` next to `clear_cache.rs` and `uninstall.rs`.
  - On Windows: a token saved and read back. The file holds no plain token (the test reads the file's bytes for the token's text). A version-1 file is converted on start with its tokens still readable. A value whose protected bytes were damaged gives the extension the explaining error while other values still read. `set` replaces it. Clear cache, uninstall and retained-data deletion counts and removals are unchanged. A failed conversion write keeps the version-1 file working.
  - On macOS and Linux: the existing tests stay green, and the documents state the protection.
  - Clipboard history on Windows, through the `Launcher` with a recording clipboard as the existing clipboard history tests use: a kept item reads back, the file holds no plain text of it, an earlier file is converted at start with its items kept, and a damaged item is explained while the others still read.
  - The later macOS and Linux slices add their own adapter tests, opt-in where a Keychain or Secret Service is needed. The Linux one uses a Secret Service provider the test starts in its own session bus, and is skipped without one.
- **Tray:**
  - The Windows adapter's shell calls go through a narrow inner seam, so a unit test can check behaviour without the real notification area: after `TaskbarCreated`, the icon is added again with the same GUID while it should show, and not while hidden; a theme change swaps the variant; the GUID is the same for the same path and differs for another; a refused GUID falls back to the numeric id.
  - The window tests in `crates/pane/tests/tray.rs` stay the boundary for the preference and the menu.
  - A Windows native smoke phase restarts Explorer and captures the icon back. The macOS native run captures the template image in light and dark menu bars. Both are release-validation evidence, as #79's plan already describes.
- **Announcements:**
  - Seam: the window tests (`crates/pane/tests/window.rs` and the accessibility support they already use), with real key events, reading GPUI's accessibility tree.
  - Checks: the query field stays focused while arrowing; no row reports focus; rows carry their position and set size; the announcer is a live region whose name and value are "<title>, <i> of <n>" after Down, with ", unavailable" and a section prefix where they apply; fast arrowing leaves only the last text; typing that keeps the same top result changes nothing, and typing that changes it updates the text once the results settle; an empty query result announces "No results"; opening a command announces its name and count. The same checks run for a command's list and the actions panel.
  - Native verification with Narrator, NVDA, VoiceOver and Orca is a release-validation item. The window tests do not establish what a screen reader speaks.
- **Hotkeys document:** a review that it matches the General page, Settings' Shortcuts page and #74's defaults. No test.
- **Crash record:**
  - Unit tests in `pane-core` for redaction (home path, user and computer names in any case, short names left alone), rotation at the size cap, the rate limit's "left out" line, and the marker's decisions with a fake process table: an ended process, a running one, a reused process id with another start time.
  - A launcher or window test starts Pane over a data folder holding a stale marker and checks the notice row and its dismissal. A clean quit through the tray's Quit in `tray.rs` leaves no marker.
  - A test confirms that a message which names a user's query or a clipboard item does not appear in the log.

## Out of Scope

- The macOS Keychain and Linux Secret Service slices' prerequisites themselves (code signing for macOS); encrypting extension data kinds other than credentials (clipboard history on Windows is in scope); the Windows Credential Manager; any change to the `credentials` interface.
- A Linux tray entry (StatusNotifierItem); new tray menu items such as a version line or Check for updates; restoring the "always show" promotion by writing the system's notification settings, as Raycast does.
- Announcements for custom views and forms, a fork of GPUI CE or AccessKit, and UI Automation's notification event (AccessKit does not raise it; the live region is used instead).
- Changing hotkey behaviour, or any document other than the hotkeys document and the decision index statement.
- Crash upload, telemetry, minidumps, restarting Pane after a crash by itself, extension logs (the "Making extensions easier to build" specification (#128)), and a log viewer inside Pane.

## Further Notes

- **Prior art:**
  - Raycast's Windows secrets: a Credential Manager entry mirrored to a DPAPI file with app-specific entropy, and "key lost but data exists: explain, never regenerate".
  - Raycast's tray: a GUID derived from a stable name, and the light or dark icon chosen from the taskbar's theme.
  - Raycast's local logging: a redactor of the user and machine names at the sink, a per-site burst limit of 10 a minute, and a crash marker consumed at the next start.
  - PowerToys Command Palette: focus kept in the search box, with one hidden assertive announcer saying "{title}, {i} of {n}" and guards against announcing programmatic selection.
  - All are recorded in the research's detailed notes and summarized in [the research](https://github.com/hoangvu12/pane/blob/main/docs/research/raycast-deep-dive.md). Pane takes the behaviour, not the code.
- The AccessKit adapters Pane pins (Windows 0.33, macOS 0.26, AT-SPI common 0.19) map a live region as described. This was read from their sources; it has not been heard from a screen reader.
- **Settled since the first draft (proposed defaults the user delegated):**
  - macOS and Linux keep today's protection until their later, flagged slices (Keychain, Secret Service), which do not block this specification;
  - clipboard history (`clipboard-history.json`) is protected on Windows as credentials are;
  - the crash notice is a one-time row in root search at the next start, plus the About page;
  - announcements use a polite live region (Command Palette uses an assertive one).
