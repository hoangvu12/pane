#133 [OPEN] Keep a local, redacted log and tell the user at the next start when Pane quit unexpectedly
## Parent

https://github.com/hoangvu12/pane/issues/129

## What to build

What Pane writes to standard error is no longer lost. On Windows a release build is a windowed program, so its diagnostics (runtime crash details, pause reasons, failures to save) go nowhere today, and on every system a crash that ends the process leaves nothing. After this ticket, every diagnostic also lands in a small, redacted log on this computer, a panic is written there before the process ends, and the next start says "Pane quit unexpectedly last time" and points at the log. Nothing is sent anywhere: no telemetry, no crash upload, no minidump.

- **One diagnostic path.** Every message Pane writes to standard error, in both crates, goes through one diagnostic function that writes to standard error as now and to the log. A developer running Pane from a terminal sees no change. Guest output is not included.
- **Where.** A logs folder in the platform's place for logs: the local application data folder on Windows, the user's Logs folder on macOS (where Console shows it), and the XDG state folder on Linux. When the data folder override is set (tests and smokes), the logs folder is inside it. The folder is readable by the user only.
- **Size and rotation.** One log appended to across starts. Past 2 MiB it is rotated, keeping at most 5 older files (6 in all, about 12 MiB at most). Each line has a UTC time and the message; each run starts with Pane's version.
- **Rate limit.** At most 10 lines a minute from one site (the message's fixed text, before its values). Beyond that, one line says how many similar lines were left out.
- **Redaction at the log's writer, before anything is written.** The home folder's path becomes `~`; the user's name becomes `<user>` and the computer's name `<computer>`, matched without regard to case and only when at least 3 characters long. Other paths are kept. Pane's own diagnostics are reviewed so none carries extension data values, local credentials, clipboard history text, query text or found file names.
- **Panics.** A panic hook writes the panic's message, location and any captured backtrace to the log before the default handling. A recovered runtime crash is logged like any other message.
- **The marker.** At start Pane writes a marker in the logs folder with its process id, start time and version. A clean quit removes it: the Pane menu's or tray's Quit, the launcher's quit path, and the system ending the session (end of session on Windows, the termination notification on macOS, SIGTERM, SIGINT or SIGHUP on Linux). At the next start, a marker whose process (same id and start time) is no longer running means that run ended unexpectedly; a marker whose process still runs belongs to another Pane on the same folder and is left alone. Each start writes its own.
- **The notice.** After an unexpected end, root search shows one root result, "Pane quit unexpectedly last time", whose action opens the logs folder in the system's file manager, the way the application update row works; no new UI element. Settings' About page shows the same notice beside its diagnostics, with "Open log folder" and "Copy diagnostics", which now include the log's location. The notice goes when the user dismisses it, opens the folder, or Pane next quits cleanly and starts again.

## Acceptance criteria

- [ ] All systems (unit, core): redaction replaces the home path, and the user's and computer's names in any case; a name shorter than 3 characters is left alone.
- [ ] All systems (unit, core): the log rotates at the size cap and never keeps more than 5 older files.
- [ ] All systems (unit, core): an 11th line from one site within a minute is held back, and one line reports how many were left out.
- [ ] All systems (unit, core, fake process table): an ended process's marker is reported as an unexpected end; a running process's marker is left alone; a reused process id with another start time counts as ended.
- [ ] All systems: a launcher or window test starting Pane over a data folder holding a stale marker shows the notice row in root search, and dismissing it removes it.
- [ ] Windows, macOS: a clean quit through the tray's Quit, in the existing tray window tests, leaves no marker.
- [ ] All systems: a test confirms a diagnostic that would name a user's query or a clipboard history item never puts that text in the log.
- [ ] All systems: every message that reaches standard error today still does, and also reaches the log through the one diagnostic path.
- [ ] All systems: a panic's message and location appear in the log.
- [ ] All systems: Settings' About page shows the notice after an unexpected end, and Copy diagnostics includes the log's location.
- [ ] CI: the branch tier is green, and a `ci-fast` verify run is green, which runs these tests on Linux and Windows and compiles the macOS leg.
