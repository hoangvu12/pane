#131 [OPEN] Bring the tray icon back after Explorer restarts, keep its identity, and match it to the taskbar's theme
## Parent

https://github.com/hoangvu12/pane/issues/129

## What to build

Pane's Windows tray icon survives an Explorer restart, keeps the user's "always show" choice across restarts and application updates, and stays legible on a light or a dark taskbar. On macOS the menu bar item shows Pane's mark instead of the word "Pane". The tray menu (Open Pane, Settings, Quit or Exit in the platform's own labels), left click summoning the launcher, and the tray preference with its rollback are unchanged.

- **Coming back after Explorer restarts (Windows).** The tray adapter's window registers the `TaskbarCreated` message. When Windows broadcasts it, the adapter adds the icon again with its identity, icon, tooltip and callback, and sets the notification version again, but only while the user's preference is to show it. A hidden icon stays hidden, and the preference record does not change. A re-add the system refuses is reported as a diagnostic and tried again at the next broadcast; the General page's switch still shows the preference.
- **A stable identity (Windows).** The icon is added with a GUID, derived as a name-based UUID from a fixed Pane namespace and the program's canonical path. It is the same across restarts and application updates (which replace the program at the same path), so Windows keeps the user's notification-area choice. A development build at another path gets its own GUID. If the system refuses the GUID, the adapter falls back to today's numeric id and says why in a diagnostic.
- **An icon that follows the taskbar (Windows).** The adapter reads the taskbar's theme from the personalization setting `SystemUsesLightTheme`, not the applications' theme and not Pane's own Appearance choice, since the taskbar can be dark while applications are light. It shows the matching variant of Pane's mark and swaps it in place when the system broadcasts a theme change (`ImmersiveColorSet`). Each variant is loaded at the notification area's small-icon size for the display's DPI. Under high contrast, the system's own colours are used where a variant would not meet contrast (proposed).
- **Icon art.** Two monochrome variants of Pane's existing mark, light and dark, embedded as multi-size icon resources; on macOS the mark is a template image. Pane's own art, not Raycast's.
- **macOS.** The status item's button shows the mark as a template image, which the system tints for light and dark menu bars and the selected state. The item has an autosave name, so a position the user Command-dragged it to is remembered.
- **Linux.** Unchanged: no tray entry, and the General page keeps saying so.
- **Out of this ticket:** a Linux tray entry, new tray menu items, and writing the system's notification settings to force "always show".

## Acceptance criteria

The Windows adapter's shell calls go through a narrow inner seam, so unit tests check behaviour without the real notification area.

- [ ] Windows (unit, through the seam): after `TaskbarCreated` the icon is added again with the same GUID, tooltip and callback while the preference is to show it, and nothing is added while it is hidden.
- [ ] Windows (unit): a refused re-add is reported and tried again at the next broadcast, and the preference record is unchanged.
- [ ] Windows (unit): the GUID is the same for the same program path across calls and differs for another path; a refused GUID falls back to the numeric id with a diagnostic.
- [ ] Windows (unit): a light taskbar selects the dark-on-light variant and a dark taskbar the other; a theme-change broadcast swaps the icon in place; Pane's own Appearance choice does not affect it.
- [ ] Windows: the icon is loaded at the small-icon size for the display's DPI.
- [ ] Windows, macOS: the existing tray window tests stay the boundary for the preference and the menu, and stay green: the menu items, left click summoning, and the preference's save and rollback are unchanged.
- [ ] macOS: the status item shows the template image, not the title "Pane", and carries an autosave name (compiled and checked on the `ci-fast` verify run's macOS leg).
- [ ] Linux: no tray entry, and the General page's explanation is unchanged.
- [ ] Release-validation evidence, not a merge gate: a Windows native smoke phase that restarts Explorer and captures the icon back, and a macOS native capture of the template image in light and dark menu bars, are added to the plan #79 already describes. This ticket does not wait for the release matrix.
- [ ] CI: the branch tier is green, and a `ci-fast` verify run is green, which runs the Windows tests above and compiles the macOS tray adapter.
