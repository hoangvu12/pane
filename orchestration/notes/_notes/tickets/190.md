#190 [OPEN] Let the runtime's epoch ticker and watchdog sleep while no guest call runs
## Parent

https://github.com/hoangvu12/pane/issues/188

## What to build

Section 2 of the parent, "The epoch ticker and the watchdog": a runtime thread's epoch ticker and watchdog sleep while no guest call is in flight on it, so a quiet Pane makes no timer wake-ups. Everything a running call is subject to stays the same. Size S-M.

Today (104a5dac):

- `deadlines::tick` (`crates/pane-core/src/runtime/deadlines.rs` ~518-537) sleeps `TICK` (10 ms) and increments the engine's epoch in a loop until the thread ends.
- `watchdog` (`runtime/supervisor.rs` ~545-551) sleeps `WATCH_EVERY` (100 ms) in a loop.
- Both are started per runtime thread (`supervisor.rs` ~486).

What to build:

- The runtime thread's `Watch` (or a sibling) says whether a guest call is in flight. The ticker and the watchdog block on it (a condvar or a parked thread) while none is, and are woken when one starts and when the thread ends.
- While a call is in flight, both behave exactly as today: a 10 ms tick, the 100 ms look, `COMPUTE_LIMIT`, and giving up on a thread that makes no progress.
- The thread's end still gets its last tick, so a guest stuck in a call reaches its epoch check and traps.
- Every kind of guest call counts as in flight: commands, root and indexed results, search, actions, schedules, services' cycles, operations, setup and preferences. So does any host work that waits on a guest.
- Watch for a call that starts between the check and the wait: no lost wake-up may leave a computing guest unticked. A test must cover it.

## Acceptance criteria

- [ ] With nothing in flight, a test hook reports the ticker and the watchdog waiting. They tick and look again as soon as a call starts.
- [ ] The existing suites stay green unchanged: pausing, stopping, unresponsive calls, a computing guest stopped after `COMPUTE_LIMIT`, a crashed runtime thread replaced, schedules and services.
- [ ] A test starts calls repeatedly at the moment the ticker goes to sleep, and every computing call is still stopped within its limit.
- [ ] `docs/pausing.md` and `docs/generations.md` say the threads sleep while no call runs.
- [ ] The measurement from #189 shows the two threads' wake-ups in `hidden-idle` near zero (Linux run). The Windows run is taken only with the user's consent, as in #189. Before and after numbers go in the results comment and the measurements document.
- [ ] CI: the branch tier is green, and a `ci-fast` verify run is green. No release matrix.
