#132 [OPEN] Announce the selected row through a live region while focus stays in the query field
## Parent

https://github.com/hoangvu12/pane/issues/129

## What to build

A screen-reader user hears what they type echoed in root search, and hears "<title>, <i> of <n>" when they move the selection. Today the selected row is reported as the query field's active descendant, which GPUI CE implements by reporting the row as focused, so a screen reader may read results instead of echoing typing. This ticket removes root search's dependence on active-descendant support.

- **Focus.** In root search, accessibility focus stays on the query field (the editable combo box). The active-descendant claim is removed from root results and computed answers, so no row reports itself as focused. Each row keeps its list-box-option role, label, description and selected state, and gains its position in the set and the set's size. A command's list, the actions panel, the footer menu and the clipboard history view get the same change wherever focus stays in a field or menu while a row is selected. A list with no field keeps focus on the list.
- **The announcer.** Each launcher window has one hidden, zero-size node of Pane's own that is a polite live region. Each announcement sets the text as both the node's name and its value: AccessKit's Windows and Linux adapters announce the name and its macOS adapter the value, so Narrator, NVDA, Orca and VoiceOver all get the same text. Each new text replaces the last, so fast arrowing collapses to where the user stopped.
- **What is announced** (in the launcher's language, English today):
  - A selection move by the user (arrows, Alt+Up/Down, Ctrl+Up/Down, the Alt-based Emacs and Vim keys, Home/End, number chords, the pointer): "<title>, <i> of <n>". An unavailable row adds ", unavailable". A move into another result section puts the section's name first ("Fallbacks: Search the web, 1 of 2").
  - Opening a command, a page or the actions panel: "<name>, <n> results" ("<n> commands" in the actions panel), then the selected row as above.
  - A list that becomes empty: "No results".
  - Typing: nothing per keystroke. Once the query's results settle, or 300 ms after the last keystroke, whichever is later, the selected row is announced only if it differs from the one last announced.
  - A selection Pane changes itself (a late result, a refreshed list): nothing, unless the selected row's identity changed.
- **Toasts.** The footer's toast stays a status live region. When a toast and the selection change at once, the toast is announced first and the selection's announcement waits for it.
- **Documents.** Root search's accessibility section and the decision index say that G2's remaining condition is a native run with each screen reader, not a GPUI change.
- **Out of this ticket:** custom views', forms' and Settings' accessibility, a fork of GPUI CE or AccessKit, and UI Automation's notification event.

## Acceptance criteria

Window tests drive real key events and read GPUI's accessibility tree, through the accessibility support the window tests already use.

- [ ] All systems: the query field keeps accessibility focus while the user arrows through root search, and no row or computed answer reports focus at any point.
- [ ] All systems: every row carries its position in the set and the set's size, alongside its role, label, description and selected state.
- [ ] All systems: after Down, the announcer is a polite live region whose name and value are both "<title>, <i> of <n>" for the selected row.
- [ ] All systems: an unavailable row's announcement ends with ", unavailable"; moving into the Fallbacks section prefixes "Fallbacks: ".
- [ ] All systems: several fast Down presses leave only the last row's text.
- [ ] All systems: typing that keeps the same top result leaves the text unchanged; typing that changes it updates the text once, after the results settle.
- [ ] All systems: a query with no results announces "No results"; opening a command announces its name and row count, then the selected row.
- [ ] All systems: a selection changed by Pane (a late result) announces nothing unless the selected row changed.
- [ ] All systems: the same focus and announcement checks pass in a command's list and the actions panel.
- [ ] All systems: a toast shown together with a selection change is announced first, and the footer's toast keeps its status role.
- [ ] Root search's accessibility document and the decision index are updated as above.
- [ ] Release-validation evidence, not a merge gate: native runs with Narrator and NVDA (Windows), VoiceOver (macOS) and Orca (Linux). The window tests do not establish what a screen reader speaks.
- [ ] CI: the branch tier is green, and a `ci-fast` verify run is green, which runs the window tests on Linux and Windows.
