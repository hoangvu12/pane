#186 [OPEN] Re-index a changed file within 10 ms by keeping the ignore rules between batches
## Parent

https://github.com/hoangvu12/pane/issues/126

## What to build

A changed file is re-indexed within the parent's target: under 10 ms, and visible to queries within 1 s. Today the p95 is 129 ms on the user's home folder ([`docs/evidence/files-174`](https://github.com/hoangvu12/pane/tree/main/docs/evidence/files-174)). Size M.

Where the time goes (read on 104a5dac; confirm with the blocker's benchmark first):

- **Every batch starts with an empty memo.** Each batch of changes, live (`look_at`, `crates/pane-core/src/file_index/indexer.rs` ~1969) or caught up (`catch_up_changes`, `file_index.rs` ~108), starts with a fresh `Admitted` memo. To decide whether a path is in scope, `Scope::context_at` (`scope.rs` ~380-410) re-reads every ancestor's ignore files from the root down: `OwnFiles::read` (~427-433) makes three stats and builds a `Gitignore` per file (~239-262). `checked()` (`indexer.rs` ~1167, `launcher/file_search.rs` ~68) does the same on every call.

What to build:

- The coordinator keeps the per-folder ignore context between batches. An entry is dropped when that folder's `.gitignore` or `.ignore` changes, when a `.git` folder appears or goes, when the global Git ignore file changes, or when the user's rules change (`file-search.json`). A change to an ignore file still re-checks the folder's entries, as today.
- The check at Enter (`checked()`) uses the same cache.
- Nothing may leave the index wrong. A stale cache that admits an ignored file, or hides a file no longer ignored, is a bug. Prefer dropping too much over too little.

## Acceptance criteria

- [ ] Tests through the `Launcher` seam with a fixture home (prior art: `crates/pane-core/tests/files.rs` and the file index's unit tests):
  - adding a `.gitignore` line hides the matching file after the index settles, and removing it shows it again;
  - a new `.git` folder starts applying its ignore rules;
  - changing the user's excluded patterns applies without a restart;
  - all of this holds across several batches.
- [ ] The benchmark's changed-file re-index p95 (deep and shallow paths) is under 10 ms on the user's machine, and the change is visible to a query within 1 s. Numbers go in the results comment beside the baseline. **Ask the user before running the benchmark there; the machine is also used for games.**
- [ ] `docs/files.md` says the scope's ignore context is kept between batches and what drops it.
- [ ] CI: the branch tier is green, and a `ci-fast` verify run is green. No release matrix.
