#183 [OPEN] Measure misses, typed-out prefixes and a multi-segment index in the file-index benchmark, and guard it in CI
## Parent

https://github.com/hoangvu12/pane/issues/126

## What to build

#174 measured the file index on the user's machine (evidence: [`docs/evidence/files-174`](https://github.com/hoangvu12/pane/tree/main/docs/evidence/files-174)). Three of the parent's Targets were missed: query p95 57 ms (target under 10 ms), a changed file re-indexed at p95 129 ms (under 10 ms), and catch-up after 10,000 changes 1.64 s (under 1 s). Before tuning, the benchmark has to measure the cases that cost the most. Today its query set (`crates/pane-core/examples/file_index_bench.rs`, `query_set`, ~487-524) is built only from names that exist. It never times:

- a query that matches nothing, the worst case, where the inside-word pass reads every term;
- the prefixes a user types on the way to a name;
- a kind filter;
- a query against an index with several segments and a live memtable.

This ticket makes the benchmark measure those cases and adds the regression guard the parent's Testing Decisions ask for. It changes no index code. Size S.

- **Query set.** Add these kinds, each reported with its own p50/p95/p99 beside the existing ones:
  - misses: words absent from the tree, including 3+ letter words, which take the inside-word pass;
  - typed-out prefixes: each prefix of a real name, from 1 character to the whole name, timed as a user's keystrokes would be;
  - a kind filter (Folder, Document);
  - inside-word fragments of real names.
  
  The overall p95 the table compares with the target covers every kind. The set stays fixed and seeded, so runs compare.
- **Index shape.** Time the queries twice: after the first index (one segment), and after a stream of changes leaves several segments and a non-empty memtable, below the merge threshold. Report both.
- **Re-index.** Report the changed-file re-index p95 for a file in a deep folder with ignore files on the way, as well as for a shallow one.
- **Regression guard.** A reduced generated tree (about 20,000 entries) runs in `ci-branch.yml`'s Linux tests job, or as an `xtask ci-tests` step, with generous ceilings that only catch large regressions. Update `docs/agents/ci.md` with what the leg now runs.

## Acceptance criteria

- [ ] `cargo xtask file-index-bench` reports misses, typed-out prefixes, the kind filter and inside-word fragments as their own rows, and the overall p95 covers them all.
- [ ] Queries are timed on a single-segment index and on a multi-segment index with a live memtable, and both are reported.
- [ ] The re-index row covers a deep path under ignore files.
- [ ] The reduced run is in CI with ceilings, and `docs/agents/ci.md` says so.
- [ ] The user's-machine numbers on the current engine are recorded as the new baseline in a results comment, and appended to `docs/evidence/files-174` (or a sibling folder), with the conditions. **The user's machine is also used for games:** ask the user before running the benchmark there. The code can merge on CI green before the numbers exist.
- [ ] CI: the branch tier is green. No release matrix.
