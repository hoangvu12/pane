## #184 (volumes)
4. Hung volumes: the root volume lookup (statfs / GetVolumePathNameW / GetDriveTypeW) runs synchronously without a time limit from Scope::root_volume and Coordinator start; a dead hard-mounted NFS/SMB share blocks the coordinator. Spec: "a stalled network mount … holds up only itself". Fix: do the lookup on a short-lived helper thread with a bounded wait (e.g. 2 s); on timeout treat the root as a network share (left out unless the switch is on, never watched) and note it in the status.
5. An away root is cached as Local: `root_volume` caches once per scope (OnceLock) and a missing root answers Local, so a USB stick unplugged at start is walked and watched once plugged in even with the switch off. Fix: do not cache an answer for a root that does not exist (or answer "unknown", treated as left out until it appears and is classified).
(The Linux root check and "added roots left out unless the switch is on" are user decisions — do NOT change them; they are reported to the user.)

## #186 (ignore-context cache) — correctness ("nothing may leave the index wrong"; prefer dropping too much)
6. Windows catch-up: without admin rights a deleted `.gitignore`/`.git` has no name in the journal, so its folder goes to `listed`; `missing_from` compares only indexed entries and hidden files are never indexed → no re-check, files the deleted rules hid stay out. `X/.git/info/exclude` is always unresolved at catch-up (its parent is not indexed). Fix: for every folder the catch-up lists/reads (`listed`, unresolved parents, any folder whose hidden children changed), drop its kept context and queue a re-check of it; treat an unresolved record under a `.git` folder as a change to that repository's folder. Correct docs/files.md's claim.
7. Kept rules never dropped where no events arrive: folders under a network root on a mapped drive/mount (no live watch), folders Linux could not watch (`unwatched`), and any root after `watch()` failed. Fix: never keep (or drop on every reconcile pass) the context of folders that are not watched live; a reconcile walk of a folder drops its kept context and re-checks it; when watch() fails for a root, do not keep contexts under it. `checked()` at Enter must read fresh for paths whose folders are not watched.
8. Linux `.git/info/exclude`: inside `.git` is not watched, so cached rules for that repository go stale (a regression vs reading fresh). Fix: on Linux, add a watch on each repository's `.git/info` folder (or the `.git` folder non-recursively) when its context is kept; if a watch cannot be added, do not keep that repository's context.
9. The re-check walk runs on the coordinator thread inside `handle`; a home `.gitignore` or global-ignore change walks every root before other live changes are applied (spec: a live change visible within 1 s). Fix: queue re-checks to the existing walk machinery so they run like other walks (between batches / interleaved), never blocking live change handling for a whole-root walk.
10. A watcher overflow forgets the cache but re-checks nothing; `reconcile` reads only folders whose mtime changed, and editing a .gitignore in place does not change the folder's mtime. Fix: after an overflow, re-check every folder holding an ignore file (or the affected root) — prefer dropping too much.
11. `WalkReport.hung_folders` names at most the first 100; `recheck_folders` only protects named ones, so the contents of the 101st+ hung folder are removed. Fix: track hung folders without the cap for protection purposes (keep the cap only for the status list) or abort removals when the cap was exceeded.
12. Linux catch-up never triggers a re-check (reconcile produces no changes for hidden files): in the Linux reconciling walk, a folder whose mtime changed and which holds (or held) an ignore file is re-checked. Document what remains.

## #185 / #187 — no correctness defects; fix these
13. Tombstones/deletion records may almost never be dropped: after a first walk leaves one large oldest segment, `tier_to_merge` prefers small similar runs and past 8 picks the smallest run, never the oldest; tombstones pile up (size on disk, currency-check cost). Fix: when tombstones (or deletion records) exceed a threshold (e.g. a fraction of the oldest segment's entries) or periodically, schedule a merge that starts at the oldest segment (still on the background thread).
14. Closing can block whichever thread drops the last Arc<FileIndex> (possibly the window's) while a merge wraps up (sort + fsync of a partial file). Fix: on close, signal the merger to abandon immediately without finishing the partial file (delete it, or leave it for the next open's cleanup), and make the join cheap; or move the final drop/join to the index's own thread.
15. If a merge panics the merger never runs again and `wait_for_merges` hangs: catch the panic in the merge thread, report it through `crate::diagnostic!`-style logging available on this branch (spec/126 has no diagnostics module — use the existing reporting idiom in file_index), mark merges as not running so waits return, and allow the next merge.
16. Reference test does not exercise the 50,000-entry stop or the CANDIDATES cap: add a small test that lowers or reaches them (a test-only constant override if the code has one; otherwise a targeted unit test of the stop with a generated set).
