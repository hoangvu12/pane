## 2. The extension contract today

- `wit/extension.wit`, package `pane:extension@0.1.0`, interface `command`, **`world extension`** (line 222) importing `commands`, `window`, `feedback`, `system`. Per-capability WITs each declare a wider world (`extension-with-data` in `data.wit`, `extension-with-file-index` in `file-index.wit`, etc.); the host bindgen targets `extension-with-file-index`.
- `command` exports today:
  - `render(launch-record) -> result<string, string>` — answers the command's screen as the JSON list tree; same `launch` each redraw while open.
  - `run(command, launch) -> result<string, string>` — no-view commands (ADR 0037), answer is a JSON object Pane shows nothing of.
  - `handle-event(callback, details) -> result<string, string>` — callback id from the tree (`{}` details; answer `{"entries": ...}` for lazy submenus).
  - `submit-form(item-id, values: list<field-value>) -> result<string, form-error>` — typed forms (text/choice fields only; `form`/`field`/`field-kind`/`text-field`/`choice` records, also carried as JSON in the tree).
  - `open-view(item-id) -> result<custom-view, string>` — custom views; resource `custom-view` with `render() -> frame` and `handle-event(view-event) -> result<_, string>`; `frame { width, height, shapes: list<shape>, value }`, `shape` = `rect`/`text` (rgb `u32` 0xRRGGBB, logical px); `view-event` = key (`left/right/up/down/home/end`; Tab/Enter/Escape stay with Pane) / pointer-down/move/up with `point`; `custom-view-info { title, label, role: color-well }` carried in the tree. Frame limits (`MAX_FRAME_SHAPES` 4096, `MAX_TEXT_CHARS` 256, `MAX_FRAME_SIZE` 4096) enforced host-side (`crates/pane-core/src/runtime.rs` ~395–460).
  - `launch-record` from `wit/commands.wit`.
- `docs/list-tree.md` — the tree's normative doc, version 1: `{"version": 1, "view": {"type": "list"|"form", ...}}`; list `title`/`items`; item `id`, `title`, `subtitle`, `actions` (`onAction` callback id or `submenu` with `entries`/`onOpen`, `title`, `section`, `style` default|destructive, per-system `shortcut`), `form` (fields with `value`), `customView`, `platforms`, `icon`, `titleTooltip`/`subtitleTooltip`, `accessories` (`text`/`date`/`tag` + `icon`/`color`/`tooltip`). Reading rules: unknown fields ignored at every level; a newer version drawn as far as understood; wrong/missing fields = the command's failure ("Pane could not read what the extension answered: …"), never a crash. Icons: `text` builtin name or packaged path, `{builtin, filled}`, `{path}` with `@light`/`@dark` variants, `{light, dark}` pair, `{url}` (data: drawn as-is, web downloaded+cached within ADR 0018 limits), `{file}` system icon, `{application}` icon ref; each with `tint` (tone/raw hex/pair), `mask` (circle/rounded-rectangle), `fallback` (≤4 deep), `tooltip`.
- Host-side parser: `crates/pane-core/src/runtime/tree.rs` — `read_view` / `read_answer` / `read_shortcut` (pub(crate)); typed `View { title, items, form: Option<ScreenForm> }`, `Item`, `ItemLook`, `Action`/`ActionKind` (Callback/Submenu), `ActionSubmenu`/`SubmenuEntries`, `Answer { entries }`, `Accessory`; **`TREE_VERSION: u64 = 1`** (line 28), `MAX_ACCESSORIES: usize = 3`. Re-exported by `crates/pane-core/src/runtime.rs`.
- Consumption: host `wasmtime::component::bindgen!` in `crates/pane-core/src/runtime.rs` (`bindings` mod, path `../../wit`, world `extension-with-file-index`; exports async). Rust SDK: `guests/pane-extension` (wit copy `guests/pane-extension/wit/`, `wit_bindgen::generate!` world `extension-with-data`, `generate_unused_types`). JS/TS: `tools/componentize-js/pane_js.py` builds each sample against `guests/js/wit/world.wit` (world `js-extension`, plus `js-command` + `pane.json` `"pane"` export options `rootResults`/`indexedResults`/`operations`/`search`/`service`); the SDK adapter is `guests/js/adapt.js`.

## 10. Gotchas (build-breaking and convention traps)

- **Never run cargo/rustc/rustfmt/clippy/xtask/npm/node locally** on this machine (user games here). All feedback via CI quick tier; polls only, no long sleeps.
- **WIT changes force component rebuilds.** Any change to exported WIT types makes Pane refuse every older-built component (ADR 0036's motivation). #235/#241/#242 change the `command` exports → every sample component must be rebuilt: Rust guests rebuild in CI (`cargo xtask guests`), but **JS/TS components are committed in `guests/prebuilt/`** — let the quick tier's `js-guests` job rebuild them and commit the artifact (`gh run download <run> --repo pane-app/pane -n js-guests -D guests/prebuilt`) **before** any verify run, or `ci-lints`' prebuilt-samples check fails. Never build the componentize toolchain locally.
- **Three copies of the contract stay in sync:** root `wit/`, `guests/pane-extension/wit/` (checked by `cargo xtask sdks`), and the shape the JS world uses (`guests/js/wit/world.wit` + `guests/js/pane.d.ts` + `adapt.js`). `TREE_VERSION` lives in `crates/pane-core/src/runtime/tree.rs`, `guests/pane-extension/src/list.rs`, and `guests/js/adapt.js` — bump together, and document every new tree field in `docs/list-tree.md` (the normative doc; specs and tickets defer to it).
- **Test files must be declared:** both `crates/pane/tests/main.rs` and `crates/pane-core/tests/main.rs` list every module; an undeclared file never compiles and `every_test_file_is_compiled` fails the build. Tests are one binary per crate (`autotests = false`).
- **Guests are a separate workspace** — `cargo check --workspace` never builds them; all guest-dependent tests read `target/guests/` (built only by `cargo xtask guests`, which CI runs in the test jobs). Nothing local needed — but a test you add must not assume guests exist without `support/guests.rs`-style asserts.
- **Tri-lingual parity is load-bearing:** `crates/pane-core/tests/samples.rs` and `pane/tests/window.rs` hold Rust/JS/TS samples to identical items, answers and errors. Any new sample (counter, timer, view sample) must exist in all three languages and behave identically; JS/TS variants come through `guests/prebuilt` (see above).
- **Fixtures encode contract rules:** `guests/fixtures/{old-api,mismatched-api}` assert the "refuses components built for an older shape, naming the change" behaviour — update them when the envelope or api version changes; `guests/fixtures/trees` is raw `wit_bindgen` (no SDK) so envelope changes rewrite it by hand.
- **Formatting:** no `rustfmt.toml`; default rustfmt (`fn_call_width`/`chain_width` 60) enforced by CI on every push — hand-format in the repo's one-item-per-line trailing-comma style; `cargo fmt --check` failures fail the quick tier before compile errors are even visible.
- **Contrast ratios:** today `ui/contrast.rs` uses 3.0 (graphics) / 4.5 (text) and `features/icons.rs` applies them; ticket 237's spec text says 2.5. Make the choice explicit (a constant change in `contrast.rs`) and cover it in window tests for light and dark (`settings.rs`' Appearance-section pattern: `choose(sc, "appearance-theme-Light")`).
- **Refresh/timers:** use the existing seams — `Launcher::with_clock` + `ManualClock` for tests (never wall-clock sleeps), `changes::channel()`/`ChangeSender` to wake the window (`app.rs::follow_changes`), and window presence (`app/presence.rs`) for "shown". Schedules/services (`launcher/schedules.rs`, `launcher/services.rs`) are the reference implementations of a clock-driven, change-channel-waking subsystem.
- **Escape/Backspace ownership:** the launcher's key dispatch (`crates/pane/src/keyboard.rs`, `app.rs`, `extension_views/form.rs::bind_keys`) already implements Escape-clears/back behaviour; the launcher-polish spec (#123) owns Backspace-on-empty — coordinate rather than duplicate, and keep Tab/Enter/Escape reserved in any canvas/key handling (as `custom_view.rs` does today).
