## Operating lessons (learned the hard way — read twice)

- **Steered messages only deliver between turns.** A chat in one long turn (they run marathon turns for hours with sleep-poll loops) never sees steers. To deliver a rule change or course correction to a working chat: wait for its turn to end, or `interrupt_chat` (cuts the turn; queued messages then process).
- **`interrupt_chat` kills the chat's background subagent jobs.** After ANY interrupt or turn cut, the chat must re-check implementer liveness before waiting: session dirs `~/.pi/agent/sessions/--home-ubuntu-pane-wt-<worktree>--/` (jsonl mtime = last activity; `.pi-subagent-locks/` mtime), worktree file mtimes, and recent CI runs on the branch. Dead implementer = remove stale lock, relaunch with a continuation prompt ("process was killed; review git status; continue").
- **A chat idle waiting on a dead background job is STALLED** — it will never wake. Resume it with a short message stating the exact on-disk state (worktree, branch tip, dirty files, last CI runs).
- Sending a message to an ARCHIVED chat un-archives it — don't bother, or re-archive.
- Background job completions wake idle chats automatically; that's the normal rhythm.
