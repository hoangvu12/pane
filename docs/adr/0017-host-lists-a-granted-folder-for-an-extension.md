# Let the host list a chosen folder's files for the Files extension

Proposed 2026-09-28 by the implementation of #29; not yet confirmed by the user. File search is a disableable default extension ([ADR 0001](0001-small-core.md), spec constraint 1), and the core owns matching, ranking and dispatch ([ADR 0006](0006-raycast-style-search-with-extension-providers.md)). A WASI 0.3 guest has no folders to read (Pane preopens none) and cannot open a file with the system's handler, so something must give it access to the folder the user chose.

The host provides that as an extension API, `pane:extension/files` with one async function, `list-folder(folder)`, which lists a folder under one bounded scan policy the host enforces on every system (regular files, breadth first in name order, at most 8 folders deep, 5,000 files and 20,000 entries, no hidden entries or links), on a thread of its own that stops when the guest's call is dropped. Opening is a new action of computed root results, `open-file(path)`, which the core performs with the system's handler for files, as it performs `open-url` for links. The Files extension, a Rust component, keeps the chosen folder in its settings, lists it on each query, matches the files and answers `open-file` results; disabling it removes them and stops any listing. The capability is available to every command, as the applications capability is ([ADR 0015](0015-host-finds-and-opens-applications-for-an-extension.md)); under Q9's trust model it is not a permission gate.

Considered and not chosen: a WASI preopen of the chosen folder, letting the guest walk it with `wasi:filesystem`. The guest would then need the host to know the folder before instantiating it, and its walk would run on the extension thread, which serves every extension's calls one at a time and cannot preempt a guest that does not yield (#18), so a large folder would hold up every other extension until the walk ends. A native helper ([ADR 0014](0014-optional-native-extension-helpers.md)) was not used, since the host already lists folders and opens files natively. An index kept by the host was not used: the slice is one folder with a documented bound, and an index belongs to a later whole-disk or watched search.

Still open: several folders or scopes, an index or file watching, content search, and whether other extensions should see a user's chosen folders.
