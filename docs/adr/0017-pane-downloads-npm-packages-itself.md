# Download npm packages with Pane's own client, checked and unpacked without scripts

Proposed 2026-09-29 by the implementation of #45; not yet confirmed by the user. ADR 0002 keeps npm as a distribution source and ADR 0012 identifies a package from npm by its name without version. The spec (US20, Q16) promises that a user installs a supported package without installing Node, npm or a compiler, while ADR 0008's managed Node is no longer the baseline: a Pane extension is WASI 0.3 components (ADR 0013), not Node code.

So Pane fetches an npm package itself, as a local folder in a tarball, rather than running npm or a managed Node. It reads the registry's abbreviated metadata for the name, takes the exact version the user names (which pins it) or else the `latest` tag (ranges and other tags are refused), downloads that version's tarball over HTTPS only from the registry's own scheme, host and port, following no redirect, and requires the registry's sha512 `dist.integrity` to match (a version with only a sha1 `shasum` is refused). The tarball is unpacked, without its top folder, into a folder of its own under Pane's data folder: only regular files and folders, each inside the package, with no absolute path, `..`, `\`, `:`, control character, trailing dot or space, or Windows device name, within 16 MiB of metadata, a 64 MiB tarball, 256 MiB unpacked and 10,000 entries, the files without execute permission. The unpacked `package.json` must name the package and version asked for. The package is then read, checked and installed exactly as a local folder is (#9, #15), copying only `pane.json`, the components it names and this system's helper files.

Nothing in the package runs to install it. npm's lifecycle scripts (`preinstall`, `install`, `postinstall`, `prepare`…) are never run and the package's own npm dependencies are never installed; the preview says so, and names the scripts and dependencies its `package.json` declares. A tarball without `pane.json` is an ordinary npm package, which Pane explains it does not run; one whose `pane.json` names a component the tarball lacks is a source-only package its author must build before publishing. There is no build step for npm packages.

The client is `ureq` with rustls and the ring provider, verifying certificates with the operating system's verifier (`rustls-platform-verifier`) rather than a bundled root list, whose license (CDLA-Permissive-2.0) is outside the audited set; `tar` and `flate2` unpack and `sha2` checks the integrity. The registry is `https://registry.npmjs.org/`. Only a registry on this computer (127.0.0.1, localhost or [::1], which may be plain HTTP and is reached without a proxy) can replace it: through `Launcher::with_npm_registry` and, in development builds only, `PANE_NPM_REGISTRY`, which the tests and smokes use with a local registry, so no check reaches the network.

Rejected: running npm or a managed Node (a runtime the user would need, and install scripts Pane would run); following the tarball URL to another host (a mirror would have to be trusted separately); a registry setting for users (enterprise registries, scoped registries and credentials are later work).

Still open: private and scoped registries and their credentials, `.npmrc`, the Windows and macOS system proxy settings (only the proxy environment variables are read), resuming or caching downloads across starts, signatures and provenance beyond the registry's integrity, automatic updates of unpinned packages (Q21), and a Git source.
